. The *Create parameter* dialog appears:
+
image::parameter-create.png[Create parameter dialog]
. In the *Parameter name* text box, enter a name for your Parameter. This name should be unique for the object, and easy for users to understand.
. Optionally, enter a description for the Parameter in the *Add a description* text box. Use this field to add additional information users might need before using this Parameter in their analysis. It is a best practice to use this field to specify the formulas this Parameter is used in, in addition to any other information you add.
. Under *Data settings*, specify the data type the Parameter must be: Integer, Double, String, Boolean, or Date. For more information about data types, refer to xref:data-types.adoc[].
. For integer or double data types, specify the allowed values: *Any*, *List*, or *Range*. For the string data type, specify either *Any* or *List*.
+
[horizontal]
Any::
Allows any value within the data type's constraints.
List:: Allows values only in the list you create. Enter a value in the *Enter value...* text box, and optionally enter what the value should display as in the *Display as...* text box. To add more values, select *+ Add row*. To delete values, select the *x* to the right of the row the value is in.
+
image::parameter-list.png[Create a list of allowed values]
Range:: Allows values only within the range you specify. In the *Minimum value* and *Maximum value* text boxes, specify the values the range begins and ends with.
+
image::parameter-range.png[Create a range of allowed values]
. For the boolean data type, optionally set custom names for `true` and `false`; for example, `0` and `1`.
. For date data type parameters, you can configure either a static default value or a dynamic default value that automatically updates based on the current date.
+
Static date default:: Use Any, List, or Range as described above, and enter a fixed default date value.
Dynamic date default:: Select Dynamic under the date parameter settings to define a default that is resolved at query time instead of being stored as a fixed date. When you choose Dynamic, you can choose from the following options:
+
[.bordered]
image::dynamic-date-calendar.png[Dynamic date type calendar selection.]
Today, yesterday, tomorrow;; These options automatically resolve to the corresponding calendar date whenever the Answer, Liveboard, or Model is opened or refreshed.
Start of, End of;; Choose Start of or End of, then select the period (for example, week, month, quarter, year) and the calendar to use (standard calendar, fiscal calendar, or a custom calendar defined for the Model). The default date is calculated at query time based on the current period and selected calendar.
+
[.bordered]
image::dynamic-date-start.png[Start of this week period.]
Custom period;; If enabled, you can define a relative period such as "start of today to 1 week ago", "end of (current week) to 1 week ago", or "start of (current month) to 1 month ago". The effective default date is recalculated each time the Answer, Model, or Liveboard runs.
+
[.bordered]
image::dynamic-date-custom.png[Define a custom period.]
. Set the default value for your Parameter:
+
--
* For Integer, Double, String, Boolean, and static Date parameters, enter or select the value this parameter should default to.
* For Boolean, the default value option is a dropdown; true and false are the only options.
* For dynamic Date parameters, the default is defined by the dynamic rule you selected (for example, Today, Start of current month, End of previous quarter) instead of a fixed calendar date.
--
. Select *Save*.
