[#27-1-0-cl-share]
[discrete]
=== Share personalized views
You can now share a private personalized view with specific users and groups, the same way you share Liveboards and Answers. Before, a view was either private (only you) or public (everyone who can see the Liveboard).

* Users with view-only access to a Liveboard can now share the views they create.
* Only users with edit access can make a view public.
* People you share a view with can open it, but they can't edit, delete, or reshare it.
* Sharing a view doesn't share its Liveboard or data sources. You can only share with users and groups who can already see the Liveboard.
* Unsharing removes the view from the recipient's list. Schedules and other items that depend on the view keep working.

[#27-1-0-cl-context-layer]
[discrete]
=== Context layer
Moving Spotter context between clusters or Orgs now keeps everything you've built. Exports include topics, entry types (business definitions, metrics, and answer plans), synonyms, scope, and source. An export from a dev environment now imports into production exactly as it was, so you no longer need to rebuild topics and synonyms.

* New Export context and Import context actions: Find them on Context sources and in the *More ⋯* menu on a data model page.
* Map data models on import: Point each data model in the file to one on the target. This lets you reuse one export across multiple Orgs without editing the file.
* Preview before you import: A dry run shows counts and errors before anything is written. Importing replaces the target's existing context, and if any part fails, nothing changes.
//* Older files still work: Export files from 26.8.0.cl still import. Recipes come in as answer plans.

NOTE: Memory TML export and import, and the *Export associated Spotter memory* option, are removed in 27.1.0.cl. Use Export context and Import context instead. Personal memory isn't included in exports.

[#27-1-0-cl-context]
[discrete]
=== Conversation context suggestions
// Naomi. jira: SCAL-333351. docs jira: SCAL-333352
// PM: Anant

Spotter can now suggest improvements to your data models and Spotter memory based on how people use Spotter. A weekly background run reviews recent Spotter conversations, finds problems that keep recurring, and lists suggested fixes on the *Context suggestions* tab of the *Context improvements* page (*Data > Context improvements*). Suggestions include adding synonyms, updating column AI context, updating a data model description, and adding business definitions or answer plans to Spotter memory.

Context suggestions require Spotter 3 and saved chats to be turned on. To enable this feature, contact ThoughtSpot Support.

[discrete]
=== dbt v2
ThoughtSpot can now import dbt Semantic Layer metrics written in the latest MetricFlow spec, used by dbt v2. These projects produce the same metric models, columns, and formulas as projects using the older spec, so you can upgrade dbt without rebuilding anything in ThoughtSpot.

* Simple metrics: Sum, count, average, min, max, median, and percentile metrics import correctly, including metrics with one or more filters.
* Ratio metrics: Ratios import with their filters, including filters on the numerator or denominator, filters on dimensions from joined models, and ratios of ratios.
* Mixed projects: Projects that use both the old and new metric formats in the same project import correctly.

[discrete]
=== Column property sync [.badge.badge-ga-relnotes]#GA#

Column property sync is now Early Access. You can now keep parts of a Model in sync with their underlying tables. Previously, column properties were not automatically synchronized with the same columns at the Model level. As a result, the link for some column properties could break when the tables used for the Model were updated.  If there were multiple Models on the same table, for changes like renaming a column or updating a description, you would have to go into each Model and update the values individually. To enable this feature, contact your administrator.

[#27-1-0-cl-timezone]
[discrete]
=== Faster time zone-aware date keyword filters [.badge.badge-early-access-relnotes]#Early Access#
// Mark. jira: SCAL-315464. docs jira: SCAL-?
// PM: Damian

Date keyword filters, such as `yesterday` or `last quarter`, on time zone-aware date columns now run faster. When a date is converted to a user's time zone, ThoughtSpot can now also send a matching range filter on the underlying date column. Your cloud data warehouse can use that range to skip partitions outside the requested period instead of scanning the full table. Your results do not change.
The same optimization applies to date filters on formulas that shift a date, such as `add_days`. For time zone-aware columns, add the optional `pruning_hint` property to the formula in the model TML.
To enable this feature, contact ThoughtSpot Support.

[#27-1-0-cl-redshift]
[discrete]
=== CSV upload in Redshift
// Rani. jira: SCAL-336297. docs jira: SCAL-336299
// PM: Damian?

You can now upload a CSV file to your Amazon Redshift connection and join it to existing tables in that connection.
To use this feature, go to Data > Utilities, and click Upload CSV.

This provides a quick and easy way to load data files that are not yet in your Redshift data warehouse.
You can create a new table from the uploaded file, or append or overwrite data in an existing table that was previously created through a CSV upload.
The maximum supported file size is 50 MB. To enable this feature, contact your ThoughtSpot administrator.
