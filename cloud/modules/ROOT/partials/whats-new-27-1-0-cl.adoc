[#27-1-0-cl-suggestion]
[discrete]
=== Liveboard suggestions and auto-learning
// Naomi. jira: SCAL-343006. docs jira: SCAL-343007
// PM: Anant

Spotter now suggests Liveboards that are good candidates to add to memory. The new *Context suggestions* tab on the *Context Center* page (*Data > Context Center*) lists each suggestion with the concepts Spotter would learn, the data models it applies to, a confidence rating, and supporting evidence such as views and charts. Select a suggestion to see why Spotter recommends it.

Liveboard suggestions require the Context Center, memory in Spotter, and the Spotter 3 experience. To enable this feature, contact ThoughtSpot Support.

For more information, see
xref:spotter-liveboard-learn.adoc[Add memory from Liveboards].

[#27-1-0-cl-context]
[discrete]
=== Conversation context suggestions
// Naomi. jira: SCAL-333351. docs jira: SCAL-333352
// PM: Anant

Spotter can now suggest improvements to your data models and Spotter memory based on how people use Spotter. A weekly background run reviews recent Spotter conversations, finds problems that keep recurring, and lists suggested fixes on the *Context suggestions* tab of the *Context improvements* page (*Data > Context improvements*). Suggestions include adding synonyms, updating column AI context, updating a data model description, and adding business definitions or answer plans to Spotter memory.

Context suggestions require Spotter 3 and saved chats to be turned on. To enable this feature, contact ThoughtSpot Support.

[#27-1-0-cl-udf]
[discrete]
=== Tenant-based column aliasing [.badge.badge-ga-relnotes]#GA#

// Naomi – Jira ID: SCAL-316034. docs jira: SCAL-348190
// PM: Damian. waiting on info.

Tenant-based column aliasing introduces the capability to define a column name or description based upon the user's membership in a ThoughtSpot Org or group. For example, Client 1 may refer to a column as Region, whilst Client 2 may refer to this as State. This feature is an extension of the language-based aliasing. Data analysts can define these aliases via CSV upload or with TML. This feature is particularly useful for embedded scenarios where the same underlying Model is leveraged across multiple clients.

For more information, see

endif::[]

[#26-4-0-cl-sync]
[discrete]
=== Column property sync [.badge.badge-ga-relnotes]#GA#

// Mary. jira: SCAL-313410. docs jira: SCAL-313411
// PM: Akshat Shah.

Column property sync is now Early Access. You can now keep parts of a Model in sync with their underlying tables. Previously, column properties were not automatically synchronized with the same columns at the Model level. As a result, the link for some column properties could break when the tables used for the Model were updated.  If there were multiple Models on the same table, for changes like renaming a column or updating a description, you would have to go into each Model and update the values individually. To enable this feature, contact your administrator.


For more information, see

xref:model-column-property-sync.adoc[Model column property sync].
