[#10-14-0-cl-stop]
[discrete]
=== Stop answer in Spotter

// Naomi. jira: SCAL-257617. docs jira: SCAL-268083
// PM: Alok. marked Commit. add gif. (background info) what's happening behind the scenes, where in the process does stop happen.

When you click the Send button to ask a question in Spotter, the button transforms into a Stop button as the answer generates. You can click the Stop button at any time before the answer finishes loading, if you decide your question was incomplete or might generate an incorrect response. Once you click the button, you can edit your input and click Send to generate a new answer.

=== Spotter coaching access

// Naomi. jira: SCAL-234908. docs jira: SCAL-267410, SCAL-268946
// PM: Anant. waiting on info

You can now give privileges to add coaching to a specific Model to any user or group. Select the more options menu on any Spotter-enabled Model you have edit access to, and click *Spotter Coaching Access*. You can use the checkbox in the pop-up that appears to grant view access to the Model if the user or group you selected did not previously have access. Granting this level of access also allows your selected user or group to edit or add natural language instructions to the Model.

[#10-14-0-cl-coaching]
[discrete]
=== Spotter context in reference questions

// Naomi. jira: SCAL-264453. docs jira: SCAL-264454
// PM: Anant.

Spotter context in coaching is now on by default and available to all users. Rather than simply training Spotter Coach to recognize search tokens in reference questions, you can now improve accuracy by adding context, natural language explanations of why those tokens apply to that answer. For example, you could add an implicit rule to a sample reference question, clarifying that `sales` should only be calculated on completed transactions.

[#10-14-0-cl-progressive]
[discrete]
=== Progressive Model filters

Progressive Model filters are now available to all users and on by default. Previously, any filter defined at the Model level applied to every query based on that Model. Now, you can define which table a filter applies to in the Model TML. Once defined, the filter only applies to queries that include columns from that specific table.
