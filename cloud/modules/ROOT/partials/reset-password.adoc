== When you do not receive an activation mail
If the users do not receive an activation email for resetting password, admin can help them regain access without knowing their password. Follow these steps:

. Navigate to *Admin settings* > *User Management* > *Users*. You can reach this option from the *All Orgs* and also the *Primary Org* menu.

. Click the *More* menu image:icon-more-10px.png[more menu icon] for the desired user > *Reset Password*.
+
[.bordered]
image::reset-password.png[Reset password]

. Admin can now generate a One-Time Password (OTP) for the user by clicking *Expire Password*.
+
An OTP is generated, which the Admin can copy and share securely with the user.

. The user can now go to the login screen and enter the OTP in place of the password.
. User is then prompted to set a new password. They can enter the OTP in place of the old password, and then set a new password for themselves.
* The password must meet the following requirements:
** It must be 8 characters or more in length.
** It must include at least 1 uppercase letter, 1 lowercase letter, 1 number, and 1 special character.
** It must pass a complexity test based on an external library. This test ensures password complexity and uniqueness by checking for known patterns or words that are too simple. If the password is not complex enough, ThoughtSpot rejects it, even if it fulfills the other requirements. Refer to the https://github.com/dropbox/zxcvbn[Dropbox password library^] for more information.
** It cannot use certain blocked words. By default, the blocked words are: your username, any part of your display name, and any blocked words your company configures. To add additional words to the blocklist, contact {support-url}.
. Once a new valid password is set, the OTP becomes invalid. All future logins use the new password.

[NOTE]
====
* Only local users, whose credentials are managed directly within ThoughtSpot, can use the password reset and OTP functionality. If the user is an SSO user, you cannot generate an OTP for password reset.
* Admins cannot see the user's password at any stage.
* OTP becomes invalid as soon the new password is generated by the user.
* Reset password option is applicable to all users irrespective of the user state whether PENDING, ACTIVE, or LOCKED etc.
====
