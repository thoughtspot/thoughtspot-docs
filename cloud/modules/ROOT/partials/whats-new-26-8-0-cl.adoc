[#26-8-0-cl-query]
[discrete]
=== Search data query cancellation
// Mary. jira: SCAL-293396. docs jira: SCAL-293397
// PM: Abhijit. confirm if EA. add picture of cancel button - removed from 26.8.0.cl new ETV of 26.9.0.cl.

ThoughtSpot now stops in-progress queries on your cloud data warehouse (CDW) when you change or abandon a search. This reduces unnecessary CDW spend and lets you iterate faster.

Previously, queries made using Search data continued running until timeout or completion even after you modified the search, navigated away, or edited an Answer. This release introduces two cancellation mechanisms:

* Implicit cancellation
+
ThoughtSpot automatically sends a cancel signal to the CDW when your action clearly indicates you no longer need the current result. For example, when you change the search bar, navigate to a different page, or open an Answer for editing from a Liveboard or Spotter.
* Explicit cancellation
+
A Cancel button is available on the *Search data* page for queries you want to stop manually.

[#26-8-0-cl-portal]
[discrete]
=== Admin portal enhancements

ThoughtSpot introduces a redesigned *Admin settings* experience with a cleaner, role-aware interface built to scale with multi-Org enterprise deployments. Settings are now grouped into focused categories — users, Orgs, features, appearance, and security.

The enhanced Admin portal reorganizes the administrative interface into four primary sections:

* *Home*: Main page for creating Orgs and Users, separate from general management. Contains the most frequently used administrative functionalities.

* *Management*: Settings and feature management that apply across the entire instance or organization.

* *Configuration*: Specific feature settings for a given organization, organized via clean sub-tabs and accordions. Includes Application Settings, Search & SpotIQ, and Customization tabs.

* *Monitor*: Dedicated space for tracking system health, operational status, and granular object and usage adoption details.

==== Org and user management

* Create, rename, and delete Orgs from one central location.
* Users, Roles, Groups, and Provisioning are now subtabs under *User Management*.
* Click any user to view their details (name, email, role, groups, and status) in an inline card without leaving the page.
* When creating a group, assign roles, nest child groups, and add users in a single workflow.
* Assign Org admins and manage users across Orgs without contacting your instance admin.
* View all Org details — creation date, creator, users, groups, and enabled feature flags — in one place.
* Separate interfaces for instance administrators and Org administrators keep each role's view focused and relevant.


==== Feature management

* Enable or disable Early Access and GA features per Org, with no impact on other Orgs and no system restart required.
* Org admins can customize styles, features, and notifications for their Org independently of instance-level defaults.
* Allocate self-service feature management to specific Orgs, giving Org admins control to toggle features for their own Org.

==== Configuration

* Application settings, customizations, AI settings, and Search and SpotIQ configuration are consolidated in one location.
* Settings are organized into collapsible sections.
* The page has two sub-tabs: *Application Settings* (auth, security, email) and *Customization* (logos, colors, styles).

==== Monitor

* System health, performance, stats, and adoption and usage data are available in a single location.

[#26-8-0-cl-csr]
[discrete]
=== Column security rules
// Mark. jira: SCAL-301698. docs jira: SCAL-301699
// PM: Akshat. add an example/ a use case. confirm how to enable.

Column security rules are generally available (Opt-in) in this release. Column security rules (CSR) let you restrict access to sensitive columns without the complexity of managing per-column shares.

Mark a column as protected and assign group access through the new *Manage access* panel — users who do not belong to an assigned group cannot see the protected column in search, Answers, or Liveboards, even if the table is shared with them. Protection is automatically inherited by Model and view columns derived from a protected base column. CSR coexists with the existing column-level security model — enabling CSR does not affect your current configuration. To enable this feature, contact {support-url}. For more information, see

// Mary. jira: SCAL-307283. docs jira: SCAL-307284
// PM: Siddhant

ThoughtSpot now protects user-created personalized views when you migrate Liveboard TML across environments. Previously, importing an updated Liveboard TML from a development environment would overwrite all views in production, including those created by end users. The username and the email of the owner of each view is now displayed in the Liveboard TML so administrators can see who owns each view, and can transfer ownership by editing that info in the Liveboard TML. Personalized views now also have Object IDs, similar to tables and model references in the Liveboard TML. With this release, ThoughtSpot uses a smart merge approach. Smart merge is only possible using the TML import APIs. Using the API, you can opt in to smart merge by passing a new field as TRUE. The UI will continue to show the original merge logic. Views that exist only in production are preserved, new views from the source TML are added, and views present in both are updated. For more information, see xref:scriptability.adoc[]. To enable this feature, contact your administrator.
