[#26-9-0-cl-cancellation]
[discrete]
=== Search data query cancellation
ThoughtSpot query cancellation for Search data is now generally available (GA). You can now stop in-progress queries on your cloud data warehouse (CDW) when you change or abandon a search. This reduces unnecessary CDW spend and lets you iterate faster.

Previously, queries made using Search data continued running until timeout or completion even after you modified the search, navigated away, or edited an Answer. This release introduces two cancellation mechanisms:

* Implicit cancellation
+
ThoughtSpot automatically sends a cancel signal to the CDW when your action clearly indicates you no longer need the current result. For example, when you change the search bar, navigate to a different page, or open an Answer for editing from a Liveboard or Spotter.
* Explicit cancellation
+
A Cancel button is available on the *Search data* page for queries you want to stop manually.

[#26-9-0-cl-admin]
[discrete]
=== Return user to last viewed screen after Admin portal refresh
The Admin portal now preserves your navigation state across browser refreshes and through back and forward navigation. This feature is generally available (GA). Previously, a refresh dropped you back to a default screen and the back button exited the Admin portal entirely.  This could be especially disruptive for cluster admins working across All Orgs and Primary Org view modes. Now the browser URL is the source of truth for the active admin tab, screen, and Org context. This means that you can link and bookmark admin pages so that they are restored exactly where you left off after a refresh.

The Command Palette (⌘K / Spotlight) has also been extended so every admin screen is searchable with sub-tab path labels navigable directly from the ⌘K overlay.

==== Early Access flag management for cluster admins

Cluster admins can now view and manage Early Access flags that are not Org-aware directly from *Admin* > *Feature Management* > *Early Access*. Previously, these flags were only accessible via CLI and did not appear in the *Feature Management* UI.

Early Access flags that are not Org-aware appear as On/Off toggles. Toggling a flag applies the change cluster-wide, with no per-Org assignment required. Org-aware Early Access flags are unaffected and retain the existing per-Org assignment experience.

This feature is visible only to cluster admins. Org Admins do not see non-Org-aware flags in *Feature Management*.

[discrete]
=== Scheduled Liveboards: dedicated connection configuration

You can now add a *Scheduled Liveboards* process type to a connection configuration, so scheduled Liveboard queries can use a separate warehouse, credentials, or non-OAuth authentication method instead of the parent connection's defaults.

Look for the new *Scheduled Liveboard* checkbox under the *Processes* policy type in Connection Configuration, alongside the existing *Row count stats* option.

[cols="1,3"]
|===
| Supported connectors | Snowflake, Databricks, Google BigQuery
| Authentication | Non-OAuth only
| Query routing | Scheduled Liveboard tasks automatically route to this configuration
| Limits | One configuration per process type; multiple processes can share a single configuration
|===

[#26-9-0-cl-aggregate]
[discrete]
=== Table summaries: table aggregate for all measure types
ThoughtSpot now supports table aggregate (TABLE_AGGR) as a selectable headline aggregation option for all measure types in tables and pivot tables, including composable measures such as sum, min, max, and count.

Previously, table aggregate was available only for non-composable measures (for example, average and unique count). This caused incorrect headline and summary values in data models with many-to-many joins, where join fan-out inflated rollup totals. With this change, you can select TABLE_AGGR for any measure to compute a true grand total across the result set.

[cols="1,3"]
|===
| Default aggregation | Unchanged for composable measures — TABLE_AGGR becomes a selectable option only, not the new default

| Incompatible measures | Constant and variable expressions do not qualify for TABLE_AGGR even when the flag is enabled

| Incompatible formulas | Summary cells for measures incompatible with table aggregate semantics render blank rather than returning an error; row-level values are unaffected

| Scope | Headline cells and summary/subtotal rows in tables and pivot tables
|===

To enable this feature, contact your administrator.
