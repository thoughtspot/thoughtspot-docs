[#26-9-0-cl-cancellation]
[discrete]
=== Search data query cancellation
ThoughtSpot query cancellation is now generally available (GA). You can now stop in-progress queries on your cloud data warehouse (CDW) when you change or abandon a search. This reduces unnecessary CDW spend and lets you iterate faster.

Previously, queries made using Search data continued running until timeout or completion even after you modified the search, navigated away, or edited an Answer. This release introduces two cancellation mechanisms:

* Implicit cancellation
+
ThoughtSpot automatically sends a cancel signal to the CDW when your action clearly indicates you no longer need the current result. For example, when you change the search bar, navigate to a different page, or open an Answer for editing from a Liveboard or Spotter.
* Explicit cancellation
+
A Cancel button is available on the *Search data* page for queries you want to stop manually.

[#26-9-0-cl-admin]
[discrete]
=== Return user to last viewed screen after Admin portal refresh
The Admin portal now preserves your navigation state across browser refreshes and through back and forward navigation. This feature is generally available (GA). Previously, a refresh dropped you back to a default screen and the back button exited the Admin portal entirely.  This could be especially disruptive for cluster admins working across All Orgs and Primary Org view modes. Now the browser URL is the source of truth for the active admin tab, screen, and Org context. This means that you can link and bookmark admin pages so that they are restored exactly where you left off after a refresh.

The Command Palette (⌘K / Spotlight) has also been extended so every admin screen is searchable with sub-tab path labels navigable directly from the ⌘K overlay.

[#26-9-0-cl-config]
[discrete]
=== Connection configuration: scheduled Liveboards process type

You can now create a dedicated connection configuration for *Scheduled Liveboards*, allowing scheduled Liveboard queries to use a separate warehouse, credentials, or non-OAuth authentication method—instead of the parent connection's default configuration.

A new *Scheduled Liveboard* checkbox has been added to the *Processes* policy type in Connection Configuration, alongside the existing *Row count stats* option.

==== Key details

[cols="1,3", options="header"]
|===
| Detail | Description

| *Supported connectors*
| Snowflake, Databricks, Google BigQuery

| *One config per process type*
| Only one configuration per process type; multiple processes can be selected under a single configuration

| *Authentication*
| Non-OAuth only; OAuth configurations display an error

| *Shared metadata*
| All configurations share the same metadata and data; only authentication type, credentials, and warehouse may differ

| *Query routing*
| Scheduled Liveboard tasks automatically use the Scheduled Liveboard configuration instead of the parent connection

| *Lifecycle*
| Configurations can be edited, enabled, or disabled after creation
|===
