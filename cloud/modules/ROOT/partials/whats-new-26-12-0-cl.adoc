=== Search across your conversations in Spotter on Liveboards
// Mary. jira: SCAL-333707. docs jira: SCAL-?
// PM: Mayur. add video.

You can now search across all your Spotter on Liveboards conversations, making it easier to find past insights, questions, and answers. This new feature allows you to quickly locate any prior interaction, improving your ability to revisit previous discussions and discover valuable information in your chat history. No more searching each conversation individually—use global search to find relevant content wherever it appears.
////
You can now search across your saved Spotter conversations directly from the chat panel, without scrolling through the full history list.

A new Search box appears at the top of the chat panel. As you type, Spotter searches both conversation titles and the full transcripts and returns matching conversations highlighting where the match was found.

Key details:
* Typo-tolerant matching — results tolerate minor spelling errors, so forcast finds forecast.
* Searches your conversations only — results are strictly scoped to your own saved chats. Shared-to-me conversations are not included.
* Results within 5 seconds — new and renamed conversations become searchable within 5 seconds of the change.
* Filters — narrow results by date range, data model (worksheet), or agent.
* Unsaved chats cannot be searched — the search scope matches the chat history list exactly. If chat history is turned off, the search box is not available.

Conversation search is available in Spotter 3 on ThoughtSpot Cloud.

=== Variables UI: Now available for secondary Orgs and more users
// Mary. jira: SCAL-312203. docs jira: SCAL-312204
// PM: Sejal. rewrite as bullet points
////
The variables UI is now accessible to users in secondary organizations as well as a broader set of user profiles. This change helps teams leverage parameterized analytics across multiple Org contexts and makes personalization easier for more users. If your deployment uses Orgs for multi-tenant or segmentation, your users now have access to variable-driven analytics and workflows.
////

Variables now support three enhancements in the Admin portal. Formula variables can be assigned a data type (such as string, integer, date, or boolean) at creation, ensuring values are validated against the target column type and resolve correctly in RLS rules and formulas without conversion wrappers. Variable values can now be scoped to individual users and groups in addition to Orgs, with values resolved at query time in user > group > Org > default order. A default value can also be set on a variable, used as a fallback when no scoped value matches the current user context, preventing query failures for users or Orgs without an explicitly assigned value.

=== New privileges to control content creation and analysis

// Mary. jira: SCAL-331949. docs jira: SCAL-331950
// PM: Siddhant. switch bullet list to a table and explain more. change first line to summarize rbac-- can administer schedules privilege is not related to "creating content and analyzing data"

Administrators can now use roles to control who can create content and analyze data. These new privileges are available on instances with Roles enabled:

* *Can create Liveboards*: Create, edit, copy, pin to, and delete Liveboards.
* *Can create Answers*: Search data, and create, edit, and save Answers.
* *Can analyze data*: Use Explore, Drill down, Change analysis, and Show underlying data.
* *Can administer schedules*: Manage all schedules in the Org.

All existing and new users have the first three privileges by default, so nothing changes until an administrator revokes a privilege for a group. When a privilege is revoked, the related actions are hidden for those users. All users can still view Liveboards and Answers.

[#26-12-0-cl-csr]
[discrete]
=== Column security rules: Attribute-based access control and publishing
// Mary. jira: SCAL-311897. docs jira: SCAL-312204
// PM: Sejal. add an example. How is this different from column-level security?
////
You can now secure data at the column level using Attribute-Based Access Control (ABAC) together with column security rules. This update adds publishing support, enabling administrators and data engineers to manage access and sharing with fine-grained attribute logic. With ABAC, datasets can be segmented and shared according to user attributes like department, role, or geography, improving control over sensitive data.
////

Column security rules now support attribute-based access control (ABAC), letting administrators express column visibility as a boolean rule over user attributes rather than by group membership. Existing group-based column security requires a separate group for every combination of access dimensions (role, region, tier, and so on), which becomes unmanageable at scale and cannot be applied across Orgs. ABAC rules evaluate against the attributes the user already carries from their identity system, so a single rule covers all combinations and a primary-Org admin can publish a rule that is enforced across all secondary Orgs automatically. Rules are authored in the formula editor, supported in TML and the REST API v2, and enforced everywhere column security applies: tables, Models, Answers, Liveboards, Search, and Spotter. Group-based rules continue to work unchanged alongside them.
