Reference questions and business terms are the original tools for adding context to Spotter. They let you manually define answers to common questions and explain key business terms so Spotter can use them in responses.

== These continue to work

If you have existing reference questions or business terms configured, nothing changes. They are not being removed. Spotter will continue to use them exactly as before.

You do not need to migrate anything.

== How they compare to memory from conversations

As of 26.7, Spotter can also learn context from conversations automatically. Here is how the two approaches compare:

[options="header"]
|===
| | Legacy tools | Memory from conversations
| **Created by** | You — every entry is written manually | Spotter — learned automatically from conversation
| **Retrieval** | Verbatim match — Spotter looks for exact phrasing | Semantic — works even if the question is phrased differently
| **Maintenance** | You update entries manually when things change | Spotter auto-merges and resolves conflicts over time
| **Best for** | Fixed, unchanging definitions | Business logic that evolves
|===

== For new implementations

If you are adding context to Spotter for the first time, use xref:spotter-conversation-learn.adoc[Add memory from conversations] instead. It requires no manual authoring, handles variation in how questions are phrased, and improves automatically as Spotter learns more.
