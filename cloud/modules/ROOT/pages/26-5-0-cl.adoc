<h2 id="_new_navigation_and_homepage_coming_soon"><a class="anchor" href="#_new_navigation_and_homepage_coming_soon"></a>ThoughtSpot Sage removal in 26.6.0.cl</h2>
<div class="sectionbody">
<div class="paragraph">
<p>ThoughtSpot Sage is deprecated and has reached end-of-life. It will be removed from ThoughtSpot in the 26.6.0.cl release.</p><br>
<p>When 26.6.0.cl is released, all clusters currently on Sage will be automatically upgraded to Spotter 2. Your AI usage preferences — including whether AI answer generation is enabled or disabled  will be retained as part of the migration. We recommend all administrators migrate to Spotter as soon as possible.</p>
<br>
<p>For customers using the ThoughtSpot Embed SDK, ensure your SDK is updated to the latest version before upgrading to 26.6.0.cl. Refer to <a href="deprecation">Deprecated and removed features</a> for details.</p>

=== For the Business User
[#spotterviz]
SpotterViz [.badge.badge-early-access-relnotes]#Early Access#::
// Naomi. jira: SCAL-287205. docs jira: SCAL-297930.
// PM: Rahul PJP.
ThoughtSpot can now automatically create Liveboards based on your prompts, populating them with relevant visualizations and KPIs. In response to your prompt, ThoughtSpot evaluates available data sources, creates visualizations, and lays out the information for you. After creating a Liveboard, you can enter more prompts in SpotterViz at any time to revise and refine it. To enable this feature, contact your administrator. For more information, see xref:spotter-viz.adoc[].
[#about-your]
About your cluster::
The new *About* menu item in the *Help* menu is now generally available (GA). This feature allows you to see the *Cluster ID*, *Version*, and *Cluster Timezone* for your cluster.
// Mary. jira: SCAL-296801. docs jira: SCAL-296802
// PM: Rudram Piplad.
[#edit-an]
Edit an Answer in a Liveboard::
Editing an Answer in a Liveboard is now generally available (GA). This feature adds an *Edit* button to the Answer toolbar in a Liveboard in edit mode. Click *Edit* image:edit-answer-float.png[Edit Answer from LB] to open the *Edit Answer* page, where you can modify columns, filters, and formulas. You can save or cancel changes without leaving the Liveboard.
+
For more information, see xref:liveboard-layout-edit.adoc#answer-edit[Edit an Answer from your Liveboard].
// Mary. jira: SCAL-299794. docs jira: SCAL-299795
// PM: Dilip.
[#kpi-chart]
KPI chart settings::
// Naomi – jira: SCAL-301560. docs jira: SCAL-301561
// PM: Anshul Mehta. make a video showing all of it.
ThoughtSpot introduces more granular controls for KPI charts. You can now:
+
--
* Set different colors for anomalies, indicating whether they are above or below the expected value.
* Choose to display null data as 'zero' or 'no data found'.
--
+
For more information, see
xref:chart-kpi.adoc#advanced[Advanced KPI display options].
[#collections]
Collections::

Collections are now generally available (GA). Collections in ThoughtSpot are organizational containers that can group and manage different ThoughtSpot objects into nested hierarchies similar to folders on a computer.
These objects can be Liveboards, Answers, data models, tables, and even other Collections. Collections help with content organization, curated and structured content sharing and collaboration. Additionally, you can assign different levels of access permissions for users you share your Collections with. For more information, see: xref:collections.adoc[Collections in ThoughtSpot].

// Rani – jira: SCAL-290657, docs jira: SCAL-290660
// PM: Sidharth
[#tml-support]
TML support for Collections::
You can now use ThoughtSpot Modeling Language (TML) to export Collections along with their hierarchy. Additionally, you can import Collections into new environments while retaining their complete folder structure.
+
For more information, see xref:tml-collections.adoc[TML for Collections].
// Rani. jira: SCAL-289617. docs jira: SCAL-289618
// PM: Sidharth
[#customizable-home]
Customizable home page announcement::
ThoughtSpot introduces the option to add a custom note tile to the home page where administrators can communicate important information, such as scheduled maintenance or new features to their users. This feature is generally available (GA).
+
For more information, see xref:custom-announcement-banners.adoc#homepage-announcement[Custom home page announcement].
// Mary. jira: SCAL-286342. docs jira: SCAL-286343
// PM: Rudram Piplad.

[#26-5-0-cl-data-engineer]
=== For the Data Engineer
[#spotter-memory]
Spotter memory [.badge.badge-early-access-relnotes]#Early Access#::
// Naomi. jira: SCAL-289466, SCAL-290782. docs jira: SCAL-300551, SCAL-289467, SCAL-303800
// PM: Anant. lay out process, add video.
Spotter can now build its own memory to improve answer quality over time. Memory can be generated in two ways:
[#learn-from-conversations]
Learn from conversations::: If you have coaching access, anything you ask Spotter to remember is saved as a rule and applied to future sessions. For example, telling Spotter that "active users" means users with at least three sessions. For more information, see
xref:spotter-conversation-learn.adoc[Learn from conversations].
[#learn-from-liveboard]
Learn from Liveboard::: Generate memory from your trusted Liveboards, capturing the business rules and query patterns behind your visualizations. For more information, see
xref:spotter-liveboard-learn.adoc[Learn from a Liveboard].
+
For more information, see xref:spotter-memory.adoc[]. Note that memory is only supported for Spotter 3. To enable this feature, contact your administrator.

// Naomi. docs jira: SCAL-310769
[#spotter-web]
Spotter web search connector:: The web search connector for Spotter is now a default connector, and available to all ThoughtSpot customers. The Web Search connector enables ThoughtSpot users to augment analytics workflows with real-time web search results. This allows users to bring live, external context to inform analysis in Spotter. For more information, see xref:spotter-connectors.adoc[].
[#snowflake-driver]
Snowflake driver update::
// Naomi. jira: SCAL-296362. docs jira: SCAL-296363
// PM: Prayansh.
We have updated the Snowflake driver version to 4.0.1. For more information, see xref:connections-driver-reference.adoc[].
[#column-property]
Column property sync [.badge.badge-early-access-relnotes]#Early Access#::
// Mark. jira: SCAL-221340. docs jira: SCAL-300476
// PM: Akshat Shah add image or gif.
Column property sync is now Early Access. ThoughtSpot allows you to keep parts of a Model in sync with the underlying tables in the cloud data warehouse (CDW). Previously, as tables from the CDW were updated with new information from the CDW, it would cause the link for some column properties from the table to the Model to break. If there were multiple Models on the same table, for changes like renaming a column or updating a description, you would have to go into each Model and update the values individually. To enable this feature, contact your administrator. For more information, see
xref:model-column-property-sync.adoc[Model column property sync].
[#login-activity]
Login Activity Tracking::
// Rani. jira: SCAL-291576. docs jira: SCAL-291577
// PM: Shreyash.
ThoughtSpot now has a new data model, *Login Activity Tracking*, to capture login activity of users for a ThoughtSpot instance.
Administrators can leverage this data model to build custom monitoring Liveboards, providing visibility into login timestamps, success rates, and additional session details.
For more information, see xref:system-model.adoc[System Models, tables, and views].
[#group-privilege]
Group privilege for TS:AI and BI stats data model::
// Rani. jira: SCAL-291576. docs jira: SCAL-291577
// PM: Shreyash.
*TS:AI and BI stats* now includes privilege information for each group, giving administrators a single place to review what each group is permitted to do in ThoughtSpot. For more information, see xref:data-workspace.adoc#aibistats[AI and BI Stats].

Publishing workflow::
// Mary. jira: SCAL-286678. docs jira: SCAL-296679
// PM: Sejal?
Publishing across Orgs is now generally available (GA). Publishing allows you to create an object in the Primary Org and publish it directly to target Orgs without generating duplicate copies. You can also unpublish objects across Orgs.
+
For more information, see xref:publishing.adoc[Publishing objects between Orgs].
[#snowflake-semantic]
Snowflake Semantic Views integration [.badge.badge-early-access-relnotes]#Early Access#::
ThoughtSpot introduces Snowflake Semantic Views integration. This allows you to import external semantic model definitions from Snowflake Semantic Views that are then converted into fully functional, native ThoughtSpot Models. This eliminates the need to manually recreate Models and ensures consistency. To enable this feature, contact your administrator.
+
For more information, see xref:snowflake-semantic-integration.adoc[Integrate with Snowflake Semantic Views].

[#thoughtspot-analyst]
ThoughtSpot Analyst Studio user and group sync::
// Mary. jira:SCAL-290510. docs jira: SCAL-290511
// PM: Harviish
ThoughtSpot has enhanced how users and groups are synced between ThoughtSpot and Analyst Studio. The following improvements are included to help you to administer and secure Analyst Studio:

* When a new Analyst Studio Workspace is created, users and groups in the linked ThoughtSpot Org are created in Analyst Studio.
* Users and groups created in ThoughtSpot are also created in Analyst Studio.
* Analyst Studio privileges are determined based on the privileges available to the user in ThoughtSpot.
* User group membership in ThoughtSpot is accurately reflected in Analyst Studio as well.
* If a group is deleted from ThoughtSpot, the group is also deleted from the Analyst Studio Workspace.
* If a user is deleted from ThoughtSpot or loses access to Analyst Studio, the corresponding Analyst Studio user also loses access to the Analyst Studio Workspace.
+
For more information, see
xref:analyst-studio-permissions.adoc#dependencies[Access control and permissions].
