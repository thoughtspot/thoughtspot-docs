= Act as (User impersonation)
:page-last_updated: Sep 22, 2026
:author: Rani
:linkattrs:
:experimental:
:page-layout: default-cloud-early-access
:description: Authorized administrators can start a governed, time-bounded impersonation session to view ThoughtSpot exactly as a specific user would, for troubleshooting and support.
:jira: SCAL-325380

// SOURCE: SCAL-325379, Design doc https://docs.google.com/document/d/1imxJ2jM1oBlXnupsnphvXS_I73_cA1ZMQdYYJ-tGVYE


ThoughtSpot allows authorized administrators to start a session as another user, referred to as *Act as user*. While in this mode, the administrator sees ThoughtSpot exactly as the target user does, with the same data access, role-based permissions, Org context, content visibility, and theme. Every action taken during the session is recorded in the audit log under the administrator's identity.

Use *Act as user* to:

* Reproduce permission-related issues without creating shadow accounts or requesting screen shares.
* Verify that row-level security, column-level security, and sharing rules apply correctly before rolling out changes.
* Provide support by seeing and resolving issues in the user's exact context.

== Who can use this feature

=== Administrators
[cols="1,3", options="header"]
|===
| Administrator role | Can impersonate
| Cluster Admin | Regular users and Org Admins across all Orgs
| Org Admin | Regular users in their own Org only
|===

// SOURCE: Design doc — Privilege ceiling matrix
Neither Cluster Admins nor Org Admins can impersonate themselves or another Cluster Admin.

=== Target users (consent)
// SOURCE: Design doc — USER_PREF_ALLOW_IMPERSONATION
Each user controls whether administrators can impersonate their account. The consent toggle is off by default. A user must turn on *Act as setting* in their profile before an administrator can start a session as that user.
[.bordered]
image::impersonation-3.png[Enable Act as setting ]

Click *Edit* to set the time window for which these settings will be active for impersonation. At the end of which they will be auto disabled.
[.bordered]
image::impersonation-4.png[Enable Act as setting ]
Refer to xref:user-profile.adoc#impersonation-consent[Allow administrators to act as you].

== Session behavior

=== What the administrator can do
During an impersonation session, the administrator has full access to the platform as the target user. The following actions are permanently blocked:

// SOURCE: Design doc — Forever-blocked actions
[cols="1", options="header"]
|===
| Action blocked during impersonation
| Change password, MFA settings, or email
| Issue or revoke API tokens
| Modify role or group membership
| Accept or change EULA settings
| Transfer object ownership
| Delete the user account
| Export large data sets or send data to external integrations
|===

=== Session limits and expiry
// SOURCE: Design doc — Session Lifetime, Hard Cap
Sessions end when any of the following conditions are met first:

* The administrator selects *Exit session* in the impersonation banner.
* The session reaches the cluster's standard idle timeout.
* The session reaches the *60-minute hard cap* from when impersonation started. This limit cannot be extended and applies regardless of activity.

Closing a browser tab does not end the session. All browser tabs share the same impersonation session. An administrator can have only one active impersonation session at a time.

=== What happens when a session ends
When a session ends, the administrator is signed out of ThoughtSpot.
On clusters that use SSO with automatic redirect, the identity provider re-authenticates the administrator as themselves automatically.

[NOTE]
====
// SOURCE: Design doc — IAM v2 Okta SSO section
On IAM v2 clusters with Okta SSO, the system clears the Okta SSO session on impersonation start to keep ThoughtSpot's session and the IdP session in sync. On non-auto-redirect SSO clusters, the external IdP session remains active after impersonation ends, and the administrator is re-authenticated as themselves by the IdP.
====


////
=== The impersonation banner
// SOURCE: Design doc — Component Responsibilities, always-visible banner
A persistent, non-dismissable banner appears around the perimeter of the screen for the entire session. The banner displays:

* The name of the user the administrator is acting as.
* A countdown timer showing the time remaining in the session.
* An *Exit session* button to end the session immediately.
////


== Start an impersonation session

Before you can act as a user, the user must enable the consent toggle in their profile.

. Navigate to the *Admin settings* > *User management*.
. Locate the user you want to act as.
. Click the *Act as user* option from the user's action menu.
+
[.bordered]
image::impersonation-1.png[Act as user]
+
[NOTE]
====
The *Act as user* option is visible only if the target user is an `Active` user.
====
. A colored impersonation border appears around the perimeter of the screen. You are now viewing ThoughtSpot as the target user.
+
[.bordered]
image::impersonation-5.png[Exit session]

. To end the session before it expires, click *Exit session*.
+
[.bordered]
image::impersonation-6.png[Exit session]
+
ThoughtSpot ends the session and signs you out. On SSO clusters with auto-redirect, you are automatically re-authenticated as yourself.

== Audit trail

// SOURCE: Design doc — Dual-attribution audit, Logging section
Every action taken during an impersonation session is recorded in the security audit log (`security_audit.log`) with dual attribution. Both the acting administrator's identity and the target user's identity appear on each log entry.

The following impersonation events are logged:

[cols="1,2", options="header"]
|===
| Event | When it is recorded
| `impersonation.session.start` | When a session begins
| `impersonation.session.end` | When a session ends (any reason)
| `impersonation.action.blocked` | When a blocked action is attempted
| `impersonation.privilege_ceiling_violated` | When a privilege rule prevents impersonation
| `impersonation.scope_violated` | When an Org boundary rule prevents impersonation
| `impersonation.concurrent_limit_exceeded` | When the admin already has an active session
| `impersonation.preference.changed` | When a user changes their consent toggle
|===

== Limitations

// SOURCE: Design doc — Non-Goals, Limitations sections
* The support is currently only through the ThoughtSpot UI.
* An administrator cannot impersonate themselves.
* Only one active impersonation session is allowed per administrator at a time.
* The session cannot be extended past 60 minutes.
