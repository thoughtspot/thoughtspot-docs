Before you configure Spotter and Memory, confirm you have what you need. This page covers requirements, time expectations, and who is responsible for each step.

== What you need

[options="header"]
|===
| Requirement | Details
|---|---
| **Spotter version** | Memory requires Spotter 3. xref:spotter-versions.adoc[Check which version you have].
| **Admin access** | Enabling Spotter and Memory requires ThoughtSpot admin access. If you don't have this, contact your ThoughtSpot admin before continuing.
| **LLM connection** | Memory generation requires a connected LLM. If your organization hasn't connected one yet, complete that step first.
| **Data model** | Memory only works on data models, not tables or Views.
| **Liveboards** | Identify one to three trusted Liveboards that reflect how your team queries data. You need at least one to generate your first memory.
|===

== How long this takes

Plan for about two to three hours total to set up Spotter fully. The steps are not all done by one person — see <<who-does-what,Who does what>> below.

- **Technical setup (IT admin):** ~1 hour
- **Data model review:** 30–60 minutes
- **First memory generation:** 10–20 minutes per Liveboard

[#who-does-what]
== Who does what

Setup spans three roles. All three need to be in place before Spotter is useful at scale.

[options="header"]
|===
| Task | Who
|---|---
| Enable Spotter, connect LLM, enable Memory feature | Admin
| Assign the *Can manage Spotter privilege* to your Spotter administrator | Admin
| Review and optimize data model | Analyst with data model edit access
| Generate memory from Liveboards, manage memory org-wide, set Spotter instructions | **Spotter administrator** (Can manage Spotter privilege)
| Generate memory on a specific data model | Analyst with Manage Memory access or data model edit access
| Add personal memory | Any user
|===



== Permissions at a glance

[options="header"]
|===
| Action | Required role
|---|---
| Enable or disable Spotter | Admin
| Enable or disable Memory feature | Admin
| Enable or disable personal memory | Admin
| Assign Can manage Spotter to users | Admin
| Manage memory and instructions org-wide | Can manage Spotter
| Generate memory on a specific data model | Manage Memory access or data model edit access
| Write shared memory from conversations | Manage Memory access, data model edit access, or Can manage Spotter
| Write personal memory | Any user
| View memory | Any user with access to the data model
|===

For the full permissions reference — complete feature matrix, how to assign *Can manage Spotter* privileges, and how to grant per-Model access — see xref:spotter-memory-permissions.adoc[Memory permissions and governance].
