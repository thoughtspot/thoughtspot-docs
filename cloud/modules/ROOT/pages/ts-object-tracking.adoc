= TS: Object Tracking system Model
:page-last_updated: October 13, 2026
:author: Rani
:linkattrs:
:experimental:
:description: Use the TS: Object Tracking system Model to see who created and last changed each object, and whether it is still being used.
:jira: SCAL-342645

[.badge.badge-beta]#Beta#

The *TS: Object Tracking* system Model, sometimes referred to as _Object History_, gives a complete metadata view of every Liveboard, Answer, and Model that has issued a query: who created it, when, who last changed it, and how it is being used.
It combines object metadata (author, created, modified) with the query telemetry behind xref:ai-bi-stats-data-refresh.adoc[TS: AI and BI Stats], so you can go from "this object is unused" to "here is who owns it" in a single search.

The Model has 53 columns: 9 measures and 44 attributes.
It is available from release 26.3.0.cl.

[TIP]
====
Use *Object Type* to pick Liveboards, Answers, or tables.
Use *Object Modified Time* and *Object Author Name* for ownership and staleness.
Use *User Action Time* with *Impressions* or *Active Users* to see whether anything is still being used.
Filter *Is System* = `False` to exclude background work.

Columns that start with _Object_ describe the Liveboard or Answer itself.
Columns that start with _Model_ describe the Model it is built on.
====

== Example searches

[options="header",cols="50%,50%"]
|===
| Search | Returns

| `object name object type = 'LIVEBOARD' object author name object created time object modified by name object modified time org`
| Ownership register of every Liveboard per Org.

| `object name object type object author name max user action time org user action time > 180 days ago`
| Objects with any usage in the last 180 days. Everything not on this list is a candidate for archiving.

| `object name object type object modified time object modified time < 180 days ago org`
| Objects not modified in the last 180 days. The staleness half of an archiving rule.

| `model model author name model modified by name model modified time object name object type`
| Which Liveboards and Answers depend on each Model. Use this for impact analysis before changing a Model.

| `object author name unique count object id object type`
| Content footprint per author. Find owners with large estates before they leave or change role.

| `object name org impressions active users user action time monthly object type = 'LIVEBOARD'`
| Monthly usage per Liveboard per Org. An adoption view for a product team.
|===

== Use cases

Inactive content identification for migration and archiving::
If you apply an inactivity rule, such as 180 days, this Model gives both halves of it: last modification (metadata) and last use (telemetry), per Org, with the owner to contact.

Reconciling "last viewed" discrepancies::
Check `max user action time` for the object.
Remember the two lags: metadata refreshes every 2–3 days, and telemetry is D-1.
Names for Liveboards captured before February 26, 2026 may be null.

Change audit::
*Object Modified By Name* and *Object Modified Time* answer "who changed this Liveboard last week" without opening each object.

Model impact analysis::
Before altering a Model, list every Liveboard and Answer built on it and notify those owners.

== Things to be aware of

* The Model is in Beta.
Column names are stable, but additional columns may be added.
* Only objects that have issued at least one query appear.
A Liveboard that was created but never opened is not listed until it is used.
* *Object Name* is only populated for Liveboards for activity captured after February 26, 2026.
Earlier rows show null.
* The author and modified metadata refreshes every 2–3 days.
The usage columns follow the daily query-stats refresh.
* On large clusters, open-ended searches with no date filter can be slow.
Always add a date range on *User Action Time* or *Object Modified Time*.
