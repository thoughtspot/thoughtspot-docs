[#new]
== New features and functionality

The latest release of ThoughtSpot Cloud contains several new and enhanced features.

[#26-8-0-cl-business-user]
=== For the Business User

[#spotterviz-insights]
SpotterViz insight tiles [.badge.badge-early-access-relnotes]#Early Access#::

// Naomi. jira: SCAL-309017. docs jira: SCAL-309018
// PM: Rahul PJP. add to user side. add screenshot.

Insight tiles display AI-generated text analysis on a Liveboard. You configure the tile with instructions that define how the data should be interpreted — including which signals to surface and what conditions should be flagged. Each time the Liveboard loads, the agent executes those instructions against the current data and produces a text output. The tile supports outputs ranging from a single summary sentence to a multi-step analysis, depending on how the prompt is written. To enable this feature, contact your ThoughtSpot administrator. For more information, see xref:spotter-viz.adoc#insight[SpotterViz insight tiles].

[#command-palette]
Command palette enhancements::
// Mark. jira: SCAL-305208. docs jira: SCAL-305209
// PM: Rudram
The command palette (kbd:[`Cmd`] + kbd:[`K`] on Mac / kbd:[`Ctrl`] + kbd:[`K`] on Windows and Linux) includes several enhancements in this release:

* Smarter search results — Search results are now ranked by relevance, surfacing the most useful answers, Liveboards, and destinations based on your query and usage history.
* Navigate with / filters — Type /navigate in the palette to scope results to application destinations, including sub-section headings. Navigation results respect your role and permissions, so you only see sections you can access.
* Onboarding tips — First-time users see contextual guidance in the palette's empty state, helping you discover what the command palette can do without leaving your current page.
* Updated visual design — Refreshed color tokens bring the palette's appearance in line with the latest ThoughtSpot design system.
+
For more information, see
xref:thoughtspot-homepage.adoc#command-palette[Command palette].

[#continuous-liveboard]
Continuous Liveboard PDF experience::
The continuous Liveboard PDF experience is now generally available (GA). This feature eliminates page breaks and preserves the layout of the original Liveboard, ensuring the exported PDF remains true to the on-screen experience.
For more information, see xref:liveboard-download.adoc[Download a Liveboard].

[#timezone-aware]
Timezone-aware keywords::
// Mark. jira: SCAL-298371. docs jira: SCAL-298372
// PM: Abhijit
Time zone-aware keywords are now generally available (GA). Time zone-aware keywords ensure that relative date filters in ThoughtSpot — like "today," "yesterday," and "last 7 days" — always reflect the correct time for each user, no matter where they are in the world. This ensures that all searches, Liveboards, and dashboards automatically show time-based data that matches local business hours. For more information, see
xref:keywords-time-zone-aware.adoc[].

[#search-data]
#Search data query cancellation#::
// Mary. jira: SCAL-293396. docs jira: SCAL-293397
// PM: Abhijit. confirm if EA. add picture of cancel button. moved to 26.9.0.cl
ThoughtSpot now stops in-progress queries on your cloud data warehouse (CDW) when you change or abandon a search. This reduces unnecessary CDW spend and lets you iterate faster.
+
Previously, queries made using Search data continued running until timeout or completion even after you modified the search, navigated away, or edited an Answer. This release introduces two cancellation mechanisms:
+
* Implicit cancellation
+
ThoughtSpot automatically sends a cancel signal to the CDW when your action clearly indicates you no longer need the current result. For example, when you change the search bar, navigate to a different page, or open an Answer for editing from a Liveboard or Spotter.
* Explicit cancellation
+
A Cancel button is available on the *Search data* page for queries you want to stop manually.

[#remove-business]
Removal of auto-generated business terms::
We have removed the auto-generated business terms feature, which previously was the last step of adding coaching from a conversation. You can still manually add business terms from the Memory sources tab in the Data workspace. To learn how to create business terms, see xref:spotter-business-terms.adoc[].

[#admin-portal]
Admin portal enhancements::
ThoughtSpot introduces a redesigned *Admin settings* experience. These changes provide administrators with a cleaner, more intuitive experience that is built to scale with multi-Org, enterprise deployments. Admin settings are now organized by users, Orgs, features, appearance, and security, so you only see the sections relevant to your role. The following are some of the enhancements:

* Information architecture: The enhanced Admin settings portal reorganizes the administrative interface into four primary sections:
** Home: The foundational landing page for creating Orgs and Users, kept outside of general management. Houses the most frequently used administrative functionalities.
** Management: Contains overarching settings and feature management that apply across the entire instance or organization.
** Configuration: Houses specific feature settings for a given organization, organized via clean sub-tabs and accordions. Includes Application Settings, Search & SpotIQ, and Customization tabs.
** Monitor: A dedicated space for tracking system health, operational status, and granular object and usage adoption details.

* Org and user management
** Create, rename, and delete Orgs from one central place.
** Assign Org admins, and manage users across multiple Orgs without needing to contact your instance admin.
** View Org details such as when it was created, who it was created by, users, groups, feature flags enabled in a single spot.
** Manage Orgs and users in one interface customized for cluster administrators.
** Manage users in another interface designed just for Org administrators.
* Feature management
** Enable or disable Early Access and GA features at the Org level without affecting other Orgs or requiring a system restart.
** Org admins can customize settings like styles, features, and notifications for their own Org without touching instance defaults.
* Configuration
** Configure application settings, customizations, AI settings, and Search & SpotIQ in one place.
* Monitor
** Everything that you need to monitor your system's health, performance, stats, adoption and usage is available in the same location.

NOTE: This feature will be released to customers throughout 26.8.0.cl. To inquire about the status of your deployment or for assistance, contact {support-url}.

For more information, see xref:admin-portal-2.adoc[Admin settings portal enhancements].

User-defined column aliases::

Column aliasing for UDF columns is now generally available (GA). You define context-aware display names for columns in a Model, so that different users see the column names that are meaningful to them — based on their ThoughtSpot group, Org, or preferred language. A single Model can serve multiple client groups or locales without the need to maintain separate replicas, reducing complexity and memory overhead. [#column-security-rules]
Column security rules::
// Mark. jira: SCAL-301698. docs jira: SCAL-301699
// PM: Damian. add screenshot of Manage access panel.
Column security rules are generally available (Opt-in) in this release. Column security rules (CSR) let you restrict access to sensitive columns without the complexity of managing per-column shares. Mark a column as protected and assign group access through the new *Manage access* panel — users who do not belong to an assigned group cannot see the protected column in search, Answers, or Liveboards, even if the table is shared with them. Protection is automatically inherited by worksheet, model, and view columns derived from a protected base column. CSR coexists with the existing column-level security model — enabling CSR does not affect your current configuration. To enable this feature, contact {support-url}. For more information, see xref:column-security-rules.adoc[Column security rules].

[#personalized-view]
Personalized views enhancements [.badge.badge-early-access-relnotes]#Early Access#::
ThoughtSpot now protects user-created personalized views when you migrate Liveboard TML across environments. Previously, importing an updated Liveboard TML from a development environment would overwrite all views in production, including those created by end users. The username and the email of the owner of each view is now displayed in the Liveboard TML so administrators can see who owns each view, and can transfer ownership by editing that info in the Liveboard TML. Personalized views now also have Object IDs, similar to tables and model references in the Liveboard TML. With this release, ThoughtSpot uses a smart merge approach. Smart merge is only possible using the TML import APIs. Using the API, you can opt in to smart merge by passing a new field as TRUE. The UI will continue to show the original merge logic. Views that exist only in production are preserved, new views from the source TML are added, and views present in both are updated.
+
To enable this feature, contact your administrator.
+
For more information, see xref:scriptability.adoc[].
