[#new.release-notes-filter]
== New features and functionality

The latest release of ThoughtSpot Cloud contains several new and enhanced features.

The features described in these release notes may have one of the following statuses.

[.borderless,width=88%]
|===
|Feature statuses

|[.badge.badge-beta-relnotes]#Beta#

Beta features are incomplete and may change before GA. They are enabled for select customers to collect feedback and have limited documentation. Beta features are disabled by default. Your administrator must contact {support-url} to enable them.

|[.badge.badge-early-access-relnotes]#Early Access#

Early Access features are complete and supported, but not yet enabled by default. You can try them before GA, with full documentation available. Early Access features are disabled by default. Refer to the feature documentation for how to enable them.

|[.badge.badge-ga-relnotes]#GA#

General Availability (GA) features are usually enabled by default for all customers. They are fully supported. If the GA feature is not enabled by default, the process for enabling it is noted in the documentation.
|===

[#26-11-0-cl-x-lb]
Spotter on Liveboards [.badge.badge-early-access-relnotes]#Early Access#::
You can now open Spotter from a Liveboard, and Spotter is now grounded in the context of that Liveboard — its tabs, visualizations, and the effective filters and time ranges applied to each chart.
You can ask questions like "why did revenue drop in Q3?" or "summarize what you see on this Liveboard" and Spotter reads the actual live data behind each visualization to answer, without you having to re-specify your filters or date range.
Multi-step tasks — such as building a forecast, running a why analysis, and charting the result — now stay in a single conversation context across Spotter and Liveboard, with each step tracked so long tasks remain on course. To enable this feature, contact {support-url}.

[#26-11-0-cl-spotter-x]
Admin panel changes for Spotter on Liveboards [.badge.badge-ga-relnotes]#GA#::
ThoughtSpot introduces *Spotter on Liveboards* — a redesigned Spotter that is available across Liveboards, the Homepage, embedded ThoughtSpot, REST API, MCP, Slack, and Teams from a single toggle.
Administrators can choose the experience under *Admin* > *ThoughtSpot AI* > *Choose Spotter 3 Liveboard Experience*.
New clusters default to the New experience with Spotter 3 enabled; existing Spotter 3 clusters remain on the Classic experience after upgrading to 26.11 and can switch to New at any time.
The Spotter 3 capabilities section now shows only the settings relevant to the active experience, and every setting defaults to enabled on new clusters.

[#personalized-views-portability]
Improved portability of personalized Liveboard views [.badge.badge-ga-relnotes]#GA#::

You can now migrate personalized Liveboard views between environments, such as from development to production, without losing them. This release introduces:

* *Smart Merge TML import*: A new `enable_personalized_view_upsert` field on the existing TML import endpoint (`POST /api/rest/2.0/metadata/tml/import`) preserves personalized views during Liveboard TML import, instead of overwriting them.
* *Ownership metadata in TML*: Personalized views now include an `author` block in TML with `username` and `user_email` attributes, allowing administrators to transfer view ownership during migration. For more information, see xref:personalized-liveboard-views.adoc#_migrate_personalized_views_across_environments[Migrate personalized views across environments].

[#26-11-0-cl-x-monitoring]
Monitoring for Spotter [.badge.badge-early-access-relnotes]#Early Access#::

Administrators can now monitor Spotter usage and review conversations from the Spotter settings menu.
Two options are available:

* *Monitor metrics*:
Opens a Spotter usage metrics Liveboard in a new tab.

* *Monitor all chats*:
Opens a side panel with a searchable, filterable, and sortable list of all Spotter conversations in your organization.

Administrators can preview conversations, download the list as a CSV, and filter by user, agent, data source, date range, and more.
Selecting a conversation opens a detailed view of the full message history, tool calls, and execution timings.

To enable Spotter chat monitoring, contact {support-url}.

Data Cache for modeled sources [.badge.badge-ga-relnotes]#GA#::
ThoughtSpot now supports model-level caching with Data Cache. Data Cache copies frequently queried data from your cloud data warehouse into ThoughtSpot-managed storage, so eligible queries are served from the cache instead of running on your warehouse. This means faster answers and lower warehouse compute costs. Once Data Cache is enabled for your cluster, data model editors can turn on caching for individual Models from the new Caching tab in the Model editor. No SQL changes, TML edits, or manual configuration are required. ThoughtSpot automatically routes queries to the cache when the requested data is available, and falls back to your live warehouse when it isn't, so results are always correct. To enable this feature, contact {support-url}.

[#26-11-0-cl-org-deletion]
Handling queries post Org deletion [.badge.badge-ga-relnotes]#GA#::
Previously, deleting an Org in ThoughtSpot stopped user-initiated queries immediately, but background processes — including scheduled Liveboard reports, alerts, and search indexing — continued to run warehouse queries against the deleted Org's connections for up to 7 days during the deletion grace period, resulting in unexpected warehouse spend.
ThoughtSpot now stops all warehouse query execution for deleted Orgs immediately at deletion time.
Deleted Orgs remain restorable during the grace period; the query block is automatically lifted if an Org is restored.
