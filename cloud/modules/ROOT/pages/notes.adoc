[#new]
== New features and functionality

The latest release of ThoughtSpot Cloud contains several new and enhanced features.
[#26-3-0-cl-business-user]
=== For the Business User



// Naomi. jira: SCAL-287205. docs jira: SCAL-297930. create gif.
// PM: Dilip
SpotterViz ::

ThoughtSpot can now autonomously create Liveboards based on your prompts, populating them with relevant visualizations and KPIs. In response to your query, ThoughtSpot evaluates available data sources, creates analysis, and lays out the information for you. After creating a Liveboard, you can enter more prompts in SpotterViz at any time to revise and refine it. For more information, see xref:spotter-viz.adoc[].


// Naomi – jira: SCAL-265718. docs jira: SCAL-265719
// PM: Anshul Mehta
KPI chart settings::
ThoughtSpot introduces more granular controls for KPI charts. You can now:
+
--
* Decide how missing dates are displayed (as gaps, ignored, or treated as 0).
* Specify whether to show or hide the current date, previous date, and previous value.

* Abbreviate previous month (PM) or previous quarter (PQ).

* Specify whether the measure’s increase or decrease is positive or negative.
--
+
For more information, see xref:chart-kpi.adoc#advanced[KPI charts].

// Mary – jira: SCAL-244743. docs jira: SCAL-294280
// PM: Siddhant
Improved experience for Liveboard downloads and schedules::

ThoughtSpot introduces an improved experience for Liveboard downloads and schedules:
+
--
* When you select *Download*, you can now select CSV and XLSX in addition to PDF. When you select CSV or XLSX, you can choose which visualizations to download and a bulk download of the Liveboard data is triggered instead of a static image.
* When you select *Schedule*, you can now select specific visualizations to include in the scheduled email attachment as CSV or XLSX files.
--
+
For more information, see xref:liveboard-download-pdf.adoc[] and xref:liveboard-schedule.adoc[Schedule a Liveboard job].


// Mark. jira: SCAL-260580. docs jira: SCAL-269159
// PM: Manan? Vaibhav?
Enhanced dynamic parameters in charts::
Enhanced dynamic parameters are now generally available (GA) and on by default. You can use any parameter from an axis or column name of a chart in the title or description of the Answer which contains that chart. A parameter used in the title or description always displays the value of the same parameter used in the chart itself.
+
For more information, see
xref:charts.adoc#parameters[Parameters in axis and column names of charts and tables].

// Mark. jira: SCAL-271016. docs jira: SCAL-271017
// PM: Manan/Anshul
Improved chart recommendations::

Improved chart recommendations are now generally available (GA) and on by default. When you search, ThoughtSpot can automatically suggest a chart type based on your search query. The following capabilities are improved:
+
--
* When you submit a query for the first time, ThoughtSpot analyzes the data and automatically selects the most appropriate chart.
* If you modify an existing query by adding or removing fields, ThoughtSpot retains the existing chart type unless it is forced to change.
* When you drill down into data, ThoughtSpot maintains the current chart type whenever possible.
--
+
For more information, see
xref:charts.adoc#chart-recs[Improved chart recommendations].

=== For the Analyst

// Naomi. jira: SCAL-262654. docs jira: SCAL-298489
// PM: Akshat. add image or gif.
SpotterModel::

You can now use SpotterModel to generate comprehensive, optimized Models ready to use in your analysis. SpotterModel automates table selection, join creation, and column selection, while allowing you to review and customize each step. For more information, see xref:spotter-model-create.adoc[].

// Rani. jira: SCAL-230831. docs jira: SCAL-230835
// PM: Akshat
Add user-defined ID (object ID) in TML::
You can now manage content across multiple Orgs without having to manually change the GUID of an object each time you move it between Orgs. You can directly add or edit an object ID in the TML of an Answer, table, Model, Liveboard, or View.
+
For more information, see
xref:tml.adoc#object-id[Object ID in TML files].

// Mary. jira: SCAL-284295. docs jira: SCAL-284296
// PM: Damian
Aggregate-aware Model switching::
ThoughtSpot introduces aggregate-aware query execution. This is a transparent query optimisation feature where *Search Data* automatically switches from detailed Models to associated aggregate Models. This provides a mechanism to manage and reduce cloud costs and improve query latency while maintaining insight accuracy.
+
For more information, see xref:data-modeling-settings.adoc[].

=== For the Data Engineer

// Mary. jira: SCAL-286048. docs jira: SCAL-286049
// PM: Sidharth
Admin settings::
ThoughtSpot introduces a new and improved user experience for Administration. Administration is now part of the left navigation panel.

// Naomi. jira: SCAL-280966. docs jira: SCAL-280966
// PM: Mayur. release notes only!

Rename Sage privilege to Spotter::
We have renamed the privilege that grants users access to Spotter, previously *Can preview thoughtspot sage*, to *Can use Spotter* across all user and group management interfaces.
+
To maintain consistency and avoid disrupting existing Role-Based Access Control (RBAC) setups, ThoughtSpot will not automatically rename existing system-generated roles. For customers already using RBAC, the role named *Can preview thoughtspot sage* will remain the same, even though the underlying privilege it grants has been renamed to CAN_USE_SPOTTER. ThoughtSpot recommends that administrators create a new role to align with the new *Can use Spotter* privilege.
+
As we continue the phased removal of Sage components from the product, we strongly encourage all remaining Sage users to upgrade to the Spotter AI experience.
+
For more information, see xref:spotter-enable.adoc#privilege[Enabling Spotter].

// Naomi. jira: SCAL-263976. docs jira: SCAL-281408
// PM: Sejal, Anant
Spotter coaching access::
You can now grant coaching access to users or groups from the Spotter-enabled Model you want them to coach. Users with Spotter coaching access on a data model can import or export associated coaching TML, as well as grant Spotter coaching access to other users or groups. Sharing Spotter coaching access is no longer restricted to data model editors. You can also grant Spotter coaching access to system-level Models like the Query Stats Model, and on published data models. Spotter coaching access does not require users to have edit access to the Model.
+
For more information, see xref:spotter-coaching-permissions.adoc#grant[Grant Spotter coaching access].

// Rani. jira: SCAL-287600. docs jira: SCAL-287601
// PM: Shreyash Sharma
Object Tracking::
ThoughtSpot now has a new data model, *Object Tracking*, to capture creation date, creator, last modification date, and last modifier for any supported Liveboard, Model, and Answer.
Administrators can leverage this data model to build custom monitoring Liveboards, offering visibility into who created or modified objects and when these actions occurred.
+
For more information, see xref:system-model.adoc[System Models, tables, and views].

// Naomi. jira: SCAL-286092. docs jira: SCAL-286093
// PM: Damian
Suggestion settings column::
Suggestion settings are now generally available (GA). We have added the Suggestion Settings column to Models. This is used in conjunction with row-level security to ensure that values displayed in sample values and Spotter flows are secured.
+
Where columns require that strict row-level security is applied to sample values and Spotter, then set the Suggestion Settings column as Secure Suggestions.
+
For more information, see
xref:data-modeling-suggestion-settings.adoc[Suggestion settings].

// Mary. jira: SCAL-287376, SCAL-282499. docs jira: SCAL-287377, SCAL-270663, SCAL-282500, SCAL-284624
// PM: Damian
Column-level property for strict indexing and disabling typeahead::
Column-level properties for strict indexing and disabling typeahead are now generally available (GA).
+
For more information, see xref:security-data-object.adoc#csr[Column security rules].

// Mary. jira: SCAL-281407. docs jira: SCAL-281408
// PM: Sejal.
Publishing coaching to Orgs::
ThoughtSpot now supports publishing Spotter coaching to Orgs. In addition to Org admins, now non-admin users with Spotter coaching management access on published data models in secondary Orgs can provide coaching access permissions to other users. You can import and export coaching TML and share the data model with other users. Previously, coaching was Org-specific. Coaching changes made in the primary Org are synced with the secondary Orgs where the Model is published. to enable the publishing feature, contact your administrator.
+
For more information, see xref:publishing.adoc[].

// Rani. jira: SCAL-279485. docs jira: SCAL-279486
// PM: Sidharth Misra
Delete subobjects in Collections::
To reduce the risk of accidental data loss while deleting objects from a Collection, ThoughtSpot now has an additional step to the deletion process. If you choose to delete the objects along with or without the Collection, you must explicitly type the word DELETE (in all caps) to confirm the action. If you do not type DELETE exactly as required, the deletion will not proceed.
+
For more information, see xref:collections.adoc[Collections].

// Mary. jira: SCAL-268026. docs jira: SCAL-291455
// PM: Damian
Support for formula variables in query generation::
The use of formula variables in query generation is now generally available (GA) and on by default. Formula variables can be of any data type that ThoughtSpot supports, and can be associated with a single value or list of values. Formula variables created in the primary Org can be shared with other Orgs. A formula variable created in a non-primary Org is only visible in that Org.
+
For more information, see
xref:formula-reference.adoc#formula-variables[Formula variables].

// Mary. jira: SCAL-282743. docs jira: SCAL-282744
// PM: Prayansh
dbt MetricFlow support::
ThoughtSpot introduces support for dbt MetricFlow that allows you to import semantic definitions like formulas, measures, dimensions, and metrics from dbt. This eliminates the need to maintain separate models in dbt and ThoughtSpot.
+
For more information, see xref:dbt-integration.adoc[].

// Rani. jira: SCAL-281451. docs jira: SCAL-281452
// PM: Shreyash Sharma
Org-aware provisioned user reporting::
The *Provisioned users* tab in the *AI and BI Stats* Liveboard can now be filtered by Orgs within ThoughtSpot. This allows you to see provisioned user counts and related metrics specifically for each Org, rather than just for the whole ThoughtSpot instance.
