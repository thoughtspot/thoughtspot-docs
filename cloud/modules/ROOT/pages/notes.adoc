== New features and functionality

The latest release of ThoughtSpot Cloud contains several new and enhanced features.

[#26-8-0-cl-business-user]
=== For the Business User

Spotter 3 visual redesign:: We have redesigned the experience in Spotter 3 to look more streamlined and conversational. No functional changes have been made to how Spotter defines its reasoning, the "thinking" behind the answer. The search bar options have been simplified, but no functionality has been removed.

// Naomi. jira: SCAL-283614. docs jira: SCAL-283615
// PM: Aaghran
Multiple Model selection in Spotter [.badge.badge-beta-relnotes]#Beta#:: You can now select multiple Models to search on in a single Spotter conversation. For example, you could select a Revenue Model and a Finance Model and ask a question that spans data from both. To enable this feature, contact {support-url}.

// Naomi. jira: SCAL-309689. docs jira: SCAL-309690
// PM: Mayur
Pin a chat in Spotter:: You can now pin chats to the top of the view in the Spotter side menu, so they'll be easy to find. Pinned chats are organized by which chat has the most recent activity-- most recently interacted with, or most recently pinned.

// Naomi. jira: SCAL-309059. docs jira: SCAL-309060
// PM: Peeyush
Spreadsheet on live data [.badge.badge-early-access-whats-new]#Early Access#:: Spreadsheet puts a familiar, editable grid directly on your live data. Open any ThoughtSpot data model, table, or dataset, and every column and formula you add runs as a live query against the governed model, with no export and no stale copy. Formula columns persist as governed logic, while sort, filter, conditional formatting, and text and number formatting let you shape the grid on the fly. Save your work as an Answer that stays searchable, shareable, and governed like anything else in ThoughtSpot.
+
--
* *Columns and formulas on live data*: Build new metrics with 70+ built-in functions. Every formula runs as a live query and persists as governed logic your team can reuse.
* *Shape your view instantly*: Sort, filter, conditional formatting, and text and number formatting help you focus on what matters, applied live on the data.
* *Save as a governed Answer*: Your spreadsheet becomes a searchable, shareable object with security and lineage intact, never a disconnected export.
* *Built for real datasets*: Scroll seamlessly through large result sets and switch to full-screen mode for focused analysis.
--
+
To enable this feature, contact your administrator.

// Mary. jira: SCAL-293396. docs jira: SCAL-293397
// PM: Abhijit
Search data query cancellation::
ThoughtSpot query cancellation for Search data is now generally available (GA). You can now stop in-progress queries on your cloud data warehouse (CDW) when you change or abandon a search. This reduces unnecessary CDW spend and lets you iterate faster.

Previously, queries made using Search data continued running until timeout or completion even after you modified the search, navigated away, or edited an Answer. This release introduces two cancellation mechanisms:

* Implicit cancellation
+
ThoughtSpot automatically sends a cancel signal to the CDW when your action clearly indicates you no longer need the current result. For example, when you change the search bar, navigate to a different page, or open an Answer for editing from a Liveboard or Spotter.
* Explicit cancellation
+
A Cancel button is available on the *Search data* page for queries you want to stop manually.

// Mark. jira: SCAL-313050. docs jira: SCAL-313051
// PM: Anshul
Gradient legends for charts:: You can now encode a continuous measure, like profit margin or revenue, as a color gradient directly on bar, scatter, heatmap, line, and pivot table charts. Instead of building a separate chart or data table to surface a second variable, you can enable a gradient legend on any measure column and optionally set a "Vary by" measure to drive the color scale independently of the displayed value. This makes it faster to spot outliers, patterns, and directional trends at a glance. Hovering over a data point shows the exact value of the Vary by measure in the tooltip.

// Rani. jira: SCAL-317550. docs jira: SCAL-317551
// PM: Anshul
Outline encoding support::
You can now use data to drive the outline (border) color of chart marks such as bars, arcs, and points. Bind a field to the outline color encoding to automatically generate an ordinal color palette or a continuous gradient, complete with legend and tooltip support. Outline width and dash style remain configurable per data point. Existing outline configurations are fully backward compatible.

// Mary. jira: SCAL-312449. docs jira: SCAL-?
// PM: Anshul
Unified horizontal scrollbar for charts and pivot tables::
ThoughtSpot now renders a horizontal scrollbar across all chart types. For pivot tables, this removes the previous row-header column width cap, so attribute labels render at their full natural width instead of being truncated. The scrollbar behavior is consistent across chart types and viewport sizes.

If you click *Remember this* below a Spotter answer, it triggers a command for Spotter to add the answer's specifications directly to memory. You see a preview of the exact definitions it adds to conversational memory.

NOTE: *Remember this* is only supported for Spotter 3.

// Naomi. jira: SCAL-277656, SCAL-273103. docs jira: SCAL-273104, SCAL-326606
// PM: Anant
AI context redesign:: You can now prompt the creation of AI context from the Spotter optimization tab on a Model. Note that you must have edit access to a Model to create AI context. If you enable Spotter on a Model, it triggers AI context generation automatically.

// Mary. jira: SCAL-319110. docs jira: SCAL-319128
// PM: Sidharth
Early Access flag management for cluster admins::
Cluster admins can now view and manage Early Access flags that are not Org-aware directly from *Admin* > *Feature Management* > *Early Access*. Previously, these flags were only accessible via CLI and did not appear in the *Feature Management* UI.
+
Early Access flags that are not Org-aware appear as On/Off toggles. Toggling a flag applies the change cluster-wide, with no per-Org assignment required. Org-aware Early Access flags are unaffected and retain the existing per-Org assignment experience.
+
This feature is visible only to cluster admins. Org Admins do not see non-Org-aware flags in *Feature Management*.

// Mary. jira: SCAL-312738. docs jira: SCAL-312739
// PM: Prayansh
Scheduled Liveboards: dedicated connection configuration::
You can now add a *Scheduled Liveboards* process type to a connection configuration, so scheduled Liveboard queries can use a separate warehouse, credentials, or non-OAuth authentication method instead of the parent connection's defaults.
+
Look for the new *Scheduled Liveboard* checkbox under the *Processes* policy type in Connection Configuration, alongside the existing *Row count stats* option.
+
[cols="1,3"]
|===
| Supported connectors | Snowflake, Databricks, Google BigQuery
| Authentication | Non-OAuth only
| Query routing | Scheduled Liveboard tasks automatically route to this configuration
| Limits | One configuration per process type; multiple processes can share a single configuration
|===

// Mark. jira: SCAL-292420. docs jira: SCAL-292421
// PM: Sejal
Manage and remove parameterization from the UI:: Administrators can now manage and remove parameterization on tables and connections directly from the ThoughtSpot UI. From the Data objects or Connections page, administrators can remove variable bindings from one or more objects or use the new _Manage Parameters_ option to view, edit, add, or remove individual field-to-variable mappings without starting over.

// Mary. jira: SCAL-296396. docs jira: SCAL-296397
// PM: Damian
Aggregate-aware query execution:: Aggregate-aware query execution is now generally available (GA). Search data automatically switches from detailed Models to associated aggregate Models based on query granularity, reducing cloud costs and improving query latency without affecting insight accuracy. For more information, see
xref:model-aggregate-aware.adoc[Aggregate-aware Model switching].

// Mary. jira: SCAL-318874. docs jira: SCAL-318875
// PM: Anshul
Table summaries: table aggregate for all measure types::
ThoughtSpot now supports table aggregate (TABLE_AGGR) as a selectable headline aggregation option for all measure types in tables and pivot tables, including composable measures such as sum, min, max, and count.
+
Previously, table aggregate was available only for non-composable measures (for example, average and unique count). This caused incorrect headline and summary values in data models with many-to-many joins, where join fan-out inflated rollup totals. With this change, you can select TABLE_AGGR for any measure to compute a true grand total across the result set.
+
[cols="1,3"]
|===
| Default aggregation | Unchanged for composable measures — TABLE_AGGR becomes a selectable option only, not the new default

| Incompatible measures | Constant and variable expressions do not qualify for TABLE_AGGR even when the flag is enabled

| Incompatible formulas | Summary cells for measures incompatible with table aggregate semantics render blank rather than returning an error; row-level values are unaffected

| Scope | Headline cells and summary/subtotal rows in tables and pivot tables
|===
+
To enable this feature, contact your administrator.
