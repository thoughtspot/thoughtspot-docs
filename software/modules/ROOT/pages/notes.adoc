Models in object search [.badge.badge-beta-relnotes]#Beta#::
Models are now fully discoverable through ThoughtSpot's unified search. Whether you're using the global search bar or the search results page, Models appear alongside Answers and Liveboards — making it faster and easier to find the data foundation your analyses are built on.
+
Models are indexed alongside Answers and Liveboards. When you search for a term, relevant Models surface in both the inline suggestions and the full results page, identified by a distinct icon. You can use the same filters you already use for other object types — such as author, creation date, and object type — to narrow results down to the Model you need. To enable this feature, contact {support-url}.

New charts library [.badge.badge-ga-relnotes]#GA#::

The new charts library is now generally available (GA) and is the default charting experience in ThoughtSpot. These new charts unlock sophisticated visualizations like faceted, cross-tabbed, multivariate, and bullet charts. They also resolve previous limitations by allowing multiple columns in line column charts and slicing by color with multiple measures, while providing deeper granular control over configurations such as tooltips, data labels, and axes.
+
In this release, we introduce the following new charts:

[#gradient-legends]
Gradient legends for charts [.badge.badge-ga-relnotes]#GA#:: You can now encode a continuous measure, like profit margin or revenue, as a color gradient directly in the following charts in the new charts library:
+
--
* Column (non-stacked)
* Bar (non-stacked)
* Line-column (non-stacked)
* Scatter
* Bubble
* Donut (Arc marks, where the gradient applies to the slice fill)
--
+
Instead of building a separate chart or data table to surface a second variable, you can enable a gradient legend on any measure column and optionally set a "Vary by" measure to drive the color scale independently of the displayed value. This makes it faster to spot outliers, patterns, and directional trends at a glance. Hovering over a data point shows the exact value of the "Vary by" measure in the tooltip. For more information, see xref:chart-gradient-legend.adoc[].

[#outline-encoding]
Outline encoding support [.badge.badge-ga-relnotes]#GA#::
You can now use data to drive the outline (border) color of chart markers such as bars, arcs, and points. Bind a field to the outline color encoding to automatically generate an ordinal color palette or a continuous gradient, complete with legend and tooltip support. Outline width and dash style remain configurable per data point. Existing outline configurations are fully backward compatible.
+
For more information, see xref:chart-marker-style.adoc[Chart marker styles].

Command palette [.badge.badge-ga-relnotes]#GA#::

The command palette is now generally available (GA). You can now access anything in ThoughtSpot from a single keystroke. The command palette (kbd:[`Cmd`] + kbd:[`K`] on Mac / kbd:[`Ctrl`] + kbd:[`K`] on Windows and Linux) is a global command center that unifies navigation, search, and actions across the ThoughtSpot platform. Instead of switching between menus, list pages, and contextual controls, you can find content, trigger workflows, and navigate to any part of the product — all from one place.
+
With the command palette, you can:
+
--
* Search across Liveboards, Answers, Models, and more in one place.
* Launch a new Answer, Liveboard, or Spotter chat.
* Jump to any section of ThoughtSpot directly, from Home to Admin settings.
* Type your data question and send it straight to Spotter.
* Press forward slash (/) to filter your search by Liveboards, Answers, Admin Settings, Create, Spotter, Models, Tables, and Collections.
* Search results are ranked by relevance, surfacing the most useful answers, Liveboards, and destinations based on your query and usage history.
* Navigate with / filters — Type /navigate in the palette to scope results to application destinations, including sub-section headings. Navigation results respect your role and permissions, so you only see sections you can access.
* Onboarding tips — First-time users see contextual guidance in the palette's empty state, helping you discover what the command palette can do without leaving your current page.
--
+
For more information, see xref:thoughtspot-homepage.adoc#command-palette[Command palette].

[#column-security-rules]
Column security rules [.badge.badge-ga-relnotes]#GA#::
// Mark. jira: SCAL-301698. docs jira: SCAL-301699
// PM: Damian. add screenshot of Manage access panel.
Column security rules are generally available (Opt-in) in this release. Column security rules (CSR) let you restrict access to sensitive columns without the complexity of managing per-column shares. Mark a column as protected and assign group access through the new *Manage access* panel — users who do not belong to an assigned group cannot see the protected column in search, Answers, or Liveboards, even if the table is shared with them. Protection is automatically inherited by worksheet, model, and view columns derived from a protected base column. CSR coexists with the existing column-level security model — enabling CSR does not affect your current configuration. To enable this feature, contact {support-url}. For more information, see xref:column-security-rules.adoc[Column security rules].

[#column-property]
Column property sync [.badge.badge-early-access-relnotes]#Early Access#::
// Mark. jira: SCAL-221340. docs jira: SCAL-300476
// PM: Akshat Shah add image or gif.
ThoughtSpot allows you to keep parts of a Model in sync with the underlying tables in the cloud data warehouse (CDW). Previously, as tables from the CDW were updated with new information from the CDW, it would cause the link for some column properties from the table to the Model to break. If there were multiple Models on the same table, for changes like renaming a column or updating a description, you would have to go into each Model and update the values individually. To enable this feature, contact your administrator. For more information, see
xref:model-column-property-sync.adoc[Model column property sync].

[#upgrade-paths]
== Supported Upgrade Paths

If you are running one of the following versions, you can upgrade to the {version} release:

* 26.3.0.sw to {version}
* 10.1.0.sw (or earlier) to 26.3.0.sw, then 26.3.0.sw to {version}

This includes any hotfixes or customer patches on these branches.

If you are running a different version, you must do a multiple pass upgrade.

NOTE: To successfully upgrade your ThoughtSpot cluster, all user profiles must include a valid email address. Without valid email addresses, the upgrade is blocked.
