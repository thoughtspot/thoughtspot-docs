= Liveboard filters
:page-last_updated: Nov 2, 2026
:linkattrs:
:experimental:
:page-aliases: /complex-search/pinboard-filters.adoc
:description: You can apply filters to Liveboards as well as tables and charts.
:jira: SCAL-215772, SCAL-183714, SCAL-261681, SCAL-267012, SCAL-315135

Filters, including bulk filters and exclude filters, can be applied to Liveboards
just as with tables and charts. These kinds of filters apply to an entire Liveboard,
making it easy to see only the data that you are interested in across the tables and
charts within a Liveboard.

You change the filter values on Liveboards containing visualizations that include
hidden columns, or formulas created from hidden columns. Liveboard filters are
accessible to all users who have view or edit permissions to the underlying data
source.

NOTE: To change the values of a filter on a hidden column, you must have edit access
to the data source and *Can manage data* privileges.

== Filter scope

Filters in a Liveboard can be scoped to the whole Liveboard, to a specific tab, or
to a specific group within a tab. This allows creators to apply different filters to
different parts of a Liveboard without affecting the rest of it.

=== Liveboard filters

Liveboard filters apply across all tabs. They appear in the Liveboard header and
affect every visualization on every tab that the filter is applicable to. A Liveboard
filter that is not applicable to the active tab is hidden by default on that tab.

=== Tab filters

Tab filters apply only to visualizations within a specific tab. Each instance of a
tab filter is independent — its default values, display name, and *Applicable to*
list are local to that tab. Changing a tab filter on one tab does not affect the same
column filtered on another tab.

Tab filters always appear below Liveboard-level filters in the filter bar.

=== Group filters

Group filters apply only to visualizations within a specific group inside a tab.
Their properties are local to that group instance and do not affect other groups or
tabs.

Group filters always appear below tab-level filters in the filter bar.

=== Switching filter scope

A filter or parameter is either multi-tab (Liveboard-level) or local to a specific
tab or group — never both.

* Switching a filter from multi-tab to the current tab removes it from all other tabs
and discards the global values.
* Adding a filter as multi-tab when the same column already exists as a local filter
on other tabs removes those local filters and discards their values.
* Group-level filters and parameters cannot have their scope switched. Delete the
filter and re-add it at the new scope.

=== Cascading filter values

Filter values cascade through the hierarchy:

* A value set on a Liveboard filter constrains the available options in tab and group
filters on the same column.
* A value set on a tab filter constrains group filters on the same column within that
tab.
* A value set on a group filter affects only that group.

== Filtering a Liveboard when you have limited access to its Models

When you don't have access to all of the Models used in a Liveboard, there are still
a number of capabilities available to you.

When viewing a Liveboard, you can do the following:

* Filter columns and change parameters from a Model you have access to. Filters and
parameters from an inaccessible Model remain read-only.
* Select a hidden column used as a filter from a Model. It only shows the selected
values, and you can't change them.

When editing a Liveboard, you can do the following:

* Add, edit, and remove filters and parameters from a Model you have access to. You
can't link filters to a Model that you don't have access to.

To enable this feature, contact your administrator.

If you want to make certain columns available only to a subset of users, we recommend
using xref:security-data-object.adoc#cls[column-level security].

If row-level security (RLS) is applied to the cluster, and the creator of a Liveboard
sets up default values in a Liveboard filter, the default values will be visible to
everyone who has access to the Liveboard in the filter chip preview and in the
tooltip. The data is filtered based on RLS, but the filter chip preview and tooltip
do not follow RLS.

IMPORTANT: Liveboard filters override filters of the same name in an Answer pinned
to a Liveboard.
Example: If a pinned Answer uses a filter called *city*, which is filtered on
`chicago` and `seattle` and the Liveboard uses a filter called *city*, which is
filtered on `anaheim`, `rochester`, and `winslow`, the Answer-level filter will also
display those three cities. If the Liveboard filter is set unfiltered, the
Answer-level filter will be unfiltered as well.


== When to use a Liveboard filter

Permanent Liveboard filters can be very useful when you want to apply the same
filters to more than one related visualization. You can narrow the focus of your
Liveboard for specific purposes or audiences.

When you apply a filter, the Liveboard is not automatically saved with your filter
applied. This is to encourage ad hoc filtering. Therefore, people with read-only
access can create Liveboard filters and edit the values of pre-existing filters.
You must have edit access to the Liveboard, and view access (or higher) to the
underlying data source in order to save a Liveboard filter.

[#filter-request]
NOTE: If you do not have access to the underlying data source of a Liveboard, you
can now request access from the filter modal.

image::filter-request-access.png[Request access to the underlying data source]

Note that Liveboard filters only apply to the tables and charts that are based on
Models. If a Liveboard also includes tables and charts that were created from
underlying tables, the filters don't apply to them.

To create one filter that filters visualizations based on multiple Models, you can
link the Model columns, at the Liveboard level. Refer to
xref:liveboard-filters-linked.adoc[Linked Liveboard filters].

NOTE: By default, filters apply to all tabs in the Liveboard. You can also create
tab-level or group-level filters that apply only to a specific tab or group. To
specify certain tabs or visualizations that a Liveboard filter should apply to, refer
to xref:liveboard-filters-selective.adoc[].

ThoughtSpot also supports ad-hoc filtering, so you can filter the data on your
Liveboard by selecting a data point on any visualization in the Liveboard. These
ad-hoc cross filters are not permanent, and do not appear to other users of the
Liveboard.

IMPORTANT: The default date in a Liveboard filter must be *earlier than* 12/31/9999.

== Create a Liveboard filter

You can create a filter in the Liveboard view for any Liveboard. This allows you to
easily manipulate the visualizations and view the modified presentation in one place.

Here is an example that shows you how to add a single filter to a Liveboard.
To create a Liveboard filter:

. Select the *Edit* button at the upper right of the Liveboard. If this button is
grayed out, you do not have edit privileges for the Liveboard. To resolve this,
contact your administrator or the creator of the Liveboard.

. In the top menu bar that appears, select *Add filter*.

. In the populated columns menu, select the *Add filter* icon next to the column you
would like to filter on.
+
[.bordered]
image::add_filters_menu.png[Select the filter icon that appears when you hover over
a column name in the add filters panel]

. Under *Default values > Include*, select the values to include in your Answer. The
filter modal only shows 500 values; if the column you selected has more than 500
values, you must use the filter search bar to find the additional values.
+
[.bordered]
image::column-filter-new-experience.png[Filter default values to include]

. If you want to exclude values, select *Exclude* and choose values to exclude.

. Select *Apply*.

. To save the Liveboard with these filters, select *Save* in the top menu bar.

When you apply a filter, the Liveboard is not automatically saved with your filter
applied to every object in the Liveboard that was created from a Model. Liveboard
filters do not apply to tables and charts built directly on top of base tables.

== Create a tab filter

Tab filters apply only to visualizations within a specific tab.

To add a tab filter:

. Select the *Edit* button at the upper right of the Liveboard.
. Navigate to the tab you want to add a filter to.
. In the top menu bar, select *Add filter*.
. Select the column you want to filter on.
+
NOTE: The column picker shows only columns from Models used by visualizations in the
active tab.
. Set the default values, then select *Apply*.
. Select *Save*.

Tab filters appear below Liveboard-level filters in the filter bar and are labelled
to indicate they apply to the current tab only.

NOTE: A tab with no visualizations cannot have tab filters added to it.

== Create a group filter

Group filters apply only to visualizations within a specific group inside a tab.

To add a group filter:

. Select the *Edit* button at the upper right of the Liveboard.
. Navigate to the tab that contains the group.
. Click into the group to select it.
. In the top menu bar, select *Add filter*.
. Select the column you want to filter on.
+
NOTE: The column picker shows only columns from Models used by visualizations in
that group.
. Set the default values, then select *Apply*.
. Select *Save*.

Group filters appear below tab-level filters in the filter bar.

[#apply-filters]
== Apply filters to specific visualizations or tabs

You can apply filters to only certain visualizations or tabs that you specify.
To specify the visualizations or tabs that a Liveboard filter should apply to, follow
these steps, or refer to xref:liveboard-filters-selective.adoc[Selective Liveboard
filters]:

. Select the *Edit* button at the upper right of the Liveboard. If this button is
grayed out, you do not have edit privileges for the Liveboard. To resolve this,
contact your administrator or the creator of the Liveboard.

. In the top menu bar, select *Add filter*.
. In the *Add filters* side panel, you see a list of columns. Select the filter icon
image:icon-filter-10px.png[Filter icon image] next to the column you would like to
selectively filter on.
. Specify values to include or exclude, if you did not already specify them.
. Select *Applicable to* from the filters modal side menu.
You can select or deselect entire tabs, or only choose certain visualizations.
You can also search for a visualization.
+
[.bordered]
image::liveboard-filter-applicable-to-tabs.png[Specify filtered visualizations]
. Select *Apply*.

[#relevant-filters]

NOTE: Filters and parameters that are not relevant to a tab are hidden by default
when you open and view a Liveboard. You can choose to view all filters and
parameters, including those that are not relevant to the tab, so that you can quickly
create a new view or download the Liveboard without having to switch tabs and apply
filters individually. The option to expand and view filters and parameters is only
available when there are hidden filters and parameters on the tab.

== Linked filters
You can link columns from multiple Models, to create one Liveboard filter for
visualizations that come from different Models.

To learn how to create linked filters, refer to xref:liveboard-filters-linked.adoc.

== Mandatory filters

Mark certain filters in your Liveboard as mandatory. The Liveboard's visualizations
will only load after Liveboard viewers select values for the mandatory filters.
ThoughtSpot marks mandatory filters with an asterisk in the Liveboard filter bar.

To learn how to create mandatory filters, refer to
xref:liveboard-filters-mandatory.adoc[Mandatory Liveboard filters].

[#edit-lb-filter]
== Edit a filter

Your applied filters appear in a row at the top of the Liveboard, where you can
select them to open the filter window. Depending on where you open the filter edit
modal, you have different options.

=== View mode
If you open the filter modal from *View mode*, you can only edit the values to
include or exclude.

. Click on the filter you want to edit.
. Set the new values. Click *Apply*.
. Repeat this individually for all the filters to be edited.

==== Centralized filter window

With this centralized window, you can edit the values for multiple filters and
parameters together and then apply all the changes to the Liveboard at once.

. Click any of the filters from the row at the top of the Liveboard to open the
centralized filter modal.
+
[.bordered]
image::new-filter-modal.png[Centralized filter modal]

. All your Liveboard filters will be on the left navigation of this centralized
modal. Edit multiple filters at once and click *Apply* to see the changes.
+
Click *Reset to View Default* to restore the filter settings saved for this View.

=== Edit mode
If you open the filter in the *Edit mode*, by selecting the *Edit* button at the
upper right of the Liveboard, you can edit all the filter attributes like:

* Default values of the filter
* The visualizations that the filter should apply to
* Linked filters across models
* Filter name
* Making it a mandatory filter or otherwise

You can select each filter individually to change any of these attributes, then click
*Apply*.

. Open the filter in *Edit mode*, and select *Filter options*.

. Enter the new name under *Filter display name*.

. Click *Apply*, then click *Save*.

[#order]
== Change the filter order
If your Liveboard has multiple filters, you can arrange them in the filter bar so
that they are in a logical, coherent order. This makes it easier for viewers of the
Liveboard to understand and use the filters on the Liveboard. Changing the filter
order has no effect on the filter precedence.

To change the order of filters in the filter bar, follow these steps:

. Select the *Edit* button at the upper right of the Liveboard you would like to
edit. If this button is grayed out, you do not have edit privileges for the
Liveboard. To resolve this, contact your administrator or the creator of the
Liveboard.
. Select any filter from the filter bar, and drag and drop it to a new location.
. Select *Save* in the upper right of the Liveboard.

== Delete a filter
To delete a filter, you must be in *Edit mode*.

. Click the *More* menu icon image:icon-more-10px.png[more options menu icon] for
the Liveboard, and select *Edit*.

. Hover over the filter, and select the *x* that appears.
+
image::filter_appears.png[Click the x that appears in the upper right of the filter
when you hover over it]

NOTE: Group-level filters cannot have their scope switched to a different level.
To move a group filter to tab or Liveboard scope, delete it and re-add it at the
new scope.

== Filters in schedules and exports

When contextual filtering is enabled:

* The schedule modal does not show the Liveboard's filters. Scheduled reports still
apply tab and group filters correctly to each visualization.
* Legacy PDF (visualization mode) does not show tab and group filter chips.
* CSV, XLSX, and table PDF exports for individual visualizations include all filters
across the hierarchy that are applicable to that visualization.

== Override filters

Override filters applied via the REST API report export or embed override filters
apply at the Liveboard level. They replace tab and group filters on the same column.

== Filters in TML

Tab-level filters in Liveboard TML are resolved using the tab's `id`. When editing
or generating Liveboard TML, preserve tab IDs. If tab IDs change on import, tab
filters are silently dropped.

Note the following distinction between filter and parameter fields in TML:

* `excluded_visualizations` on *filters* takes TML visualization IDs, for example
`Viz_1`.
* `excluded_container_id` on *parameter overrides* takes visualization GUIDs, not
TML IDs.

These two fields are on the same Liveboard object but use different ID types. Using
GUIDs where TML IDs are expected, or vice versa, silently drops the exclusion.
