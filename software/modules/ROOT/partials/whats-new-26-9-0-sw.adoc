The command palette is now generally available (GA). You can now access anything in ThoughtSpot from a single keystroke. The command palette (kbd:[`Cmd`] + kbd:[`K`] on Mac / kbd:[`Ctrl`] + kbd:[`K`] on Windows and Linux) is a global command center that unifies navigation, search, and actions across the ThoughtSpot platform. Instead of switching between menus, list pages, and contextual controls, you can find content, trigger workflows, and navigate to any part of the product — all from one place.

With the command palette, you can:

* Search across Liveboards, Answers, Models, and more in one place.
* Launch a new Answer, Liveboard, or Spotter chat.
* Jump to any section of ThoughtSpot directly, from Home to Admin settings.
* Type your data question and send it straight to Spotter.
* Press forward slash (/) to filter your search by Liveboards, Answers, Admin Settings, Create, Spotter, Models, Tables, and Collections.

We made the following improvements in this release:

* Smarter search results — Search results are now ranked by relevance, surfacing the most useful answers, Liveboards, and destinations based on your query and usage history.
* Navigate with / filters — Type /navigate in the palette to scope results to application destinations, including sub-section headings. Navigation results respect your role and permissions, so you only see sections you can access.
* Onboarding tips — First-time users see contextual guidance in the palette's empty state, helping you discover what the command palette can do without leaving your current page.
* Updated visual design — Refreshed color tokens bring the palette's appearance in line with the latest ThoughtSpot design system.

[#26-9-0-sw-aggregate]
[discrete]
=== Table summaries: table aggregate for all measure types
ThoughtSpot now supports table aggregate (TABLE_AGGR) as a selectable headline aggregation option for all measure types in tables and pivot tables, including composable measures such as sum, min, max, and count.

Previously, table aggregate was available only for non-composable measures (for example, average and unique count). This caused incorrect headline and summary values in data models with many-to-many joins, where join fan-out inflated rollup totals. With this change, you can select TABLE_AGGR for any measure to compute a true grand total across the result set.

[cols="1,3"]
|===
| Default aggregation | Unchanged for composable measures — TABLE_AGGR becomes a selectable option only, not the new default

| Incompatible measures | Constant and variable expressions do not qualify for TABLE_AGGR even when the flag is enabled

| Incompatible formulas | Summary cells for measures incompatible with table aggregate semantics render blank rather than returning an error; row-level values are unaffected

| Scope | Headline cells and summary/subtotal rows in tables and pivot tables
|===

To enable this feature, contact your administrator.
