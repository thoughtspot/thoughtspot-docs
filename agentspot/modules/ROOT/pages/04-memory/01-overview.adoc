= Memory Overview
:doctype: book

:icons: font

[.lead]
Memory lets agents and workflows remember things across sessions — user preferences, organizational facts, recurring rules — so users don't restate context every time.

== Why memory exists

Without memory, every conversation starts from scratch. A user has to retell the agent their team, their region, their favorite chart format, and their fiscal calendar — every single time. With memory, the agent recalls those facts automatically.

Memory is not magic. It is an explicit save/recall system:

* Facts are *saved* — by the agent (with the user's consent) or directly by the user.
* Facts are *recalled* — automatically when relevant, or explicitly by query.
* Facts are *scoped* — so a personal note doesn't leak into someone else's context.

== Memory vs session context

These are easy to confuse — they are different.

[cols="1,1,1",options="header"]
|===
|Dimension |Session context |Memory

|Lifetime
|This conversation only.
|Persists across conversations and sessions.

|Scope
|This session, this user.
|Per user, per agent, or per organization.

|What it stores
|Chat history, uploaded files, intermediate tool outputs.
|Durable facts, preferences, rules, glossary terms.

|Management
|Automatic — platform-managed.
|Explicit — saved deliberately, manageable in the UI.
|===

For session context, see xref:../01-agents/04-sessions-and-conversations.adoc[Sessions and conversations].

== Memory scopes

A memory always belongs to exactly one scope. The scope determines who sees it.

⚠️ Confirm scope names and exact partition keys with [feature owner]. Typical scopes:

[cols="1,2",options="header"]
|===
|Scope |Who sees the memory

|*User (personal)*
|The saving user. Follows them across every agent and workflow they use.

|*User + agent (personal to this agent)*
|The saving user, but only when they're using this specific agent.

|*Agent (shared)*
|Every user of this specific agent — built by the agent's creator or anyone with edit access.

|*Tenant (organization-wide)*
|Every user in the tenant. Reserved for admin-set policies.
|===

The right scope depends on the fact. A user's preferred chart type → user scope. An org-wide policy ("always exclude test accounts") → tenant scope. An agent-specific rule ("for the EMEA Pipeline Agent, default to GBP unless asked") → user+agent or agent scope, depending on whether it's personal or shared.

== Memory topics

Memories are categorised by topic. Different topics serve different purposes.

⚠️ Confirm the complete topic list with [feature owner]. Typical topics:

[cols="1,2",options="header"]
|===
|Topic |Use for

|*User personal info*
|Who the user is — name, role, team, working history.

|*User preferences*
|How the user wants responses — tone, length, format, units.

|*Rule*
|Always-on instructions for the agent (e.g. "always filter to the last 15 days").

|*Fact*
|Stable ground truths (e.g. "fiscal year starts in April," "we have ~1,500 customers").

|*Recipe*
|A reusable procedure or methodology.

|*Dictionary (`dict`)*
|Domain terminology and abbreviations (e.g. "ACV means revenue," "MQL = Marketing Qualified Lead").

|*Explicit instructions*
|Direct, named instructions from the user or agent owner for future behavior.
|===

Topic matters because it controls *when* the memory is recalled. A `rule` may be applied to every interaction (always-relevant); a `fact` may be retrieved only when semantically related to the question.

== Always-relevant vs semantic recall

Each memory is marked either *always relevant* (loaded into every interaction) or *semantically relevant* (retrieved only when similar to the current question).

* *Always-relevant* — use for rules, policies, and user preferences that should apply universally. Keep the list short; every always-relevant memory eats context window.
* *Semantic* — use for facts and definitions that only matter for some questions. Storage is cheap; recall picks only the relevant ones.

⚠️ Confirm the always-relevant cap and selection algorithm with [feature owner].

== Who can save memory

* *The agent* — automatically, with the user's consent ("Do you want me to remember that?"). Or explicitly when the user says "save this," "remember this," "make a note."
* *The user* — directly, by editing memory in the UI. See xref:03-ui-management.adoc[UI management].
* *The admin* — for tenant-scoped policies, via the admin center.

The agent never saves silently. If the agent wants to remember a fact the user didn't explicitly call out, it asks first.

== A typical example

A user says: "Remember that I work on the Sales team and prefer concise bullet-point answers."

The agent extracts two memories and saves them:

. Topic: *user personal info*. Section: *about me*. Content: "I work on the Sales team." Scope: user.
. Topic: *user preferences*. Section: *preferences*. Content: "Prefer concise, bullet-point answers." Scope: user.

Both are saved as always-relevant. Every future conversation with any agent the user touches gets both memories preloaded into context.
