== Agent

A focused assistant that does one thing well for a defined audience. An agent has:

* *Instructions* — How it works
* *Tools* — Tools it can use
* *Skills* — Special knowledge on how to do very specific tasks
* *Connectors* — Access to apps
* *Starter prompts* — Introductory messages that trigger the conversation and guide the user on how to interact with the agent

Agents are conversational: users ask questions, the agent responds, and follow-up questions stay in context within the same session.

See: xref:../01-agents/01-overview.adoc[Agents overview].

== Workflow

A repeatable, multi-step process that runs end-to-end without a human in every step. Workflows are triggered by a schedule, or a manual run. Each step is a sub-agent that does one specific job (fetch data, transform data, call a tool, evaluate a condition, etc.).

Use an agent when a person is in the loop asking questions. Use a workflow when the same series of steps needs to happen on a schedule.

For more information, see xref:../02-workflows/01-overview.adoc[Workflows overview].

== Skill

A *skill* is a capability you can attach to an agent so it can do more than answer questions. Example: the _youtube-transcript_ skill allows an agent to interpret the transcript of a YouTube video.

⚠️ Confirm your skill definition with [feature owner]. The placeholder framing used here:

* A skill bundles one or more *tools* and the instructions for when to use them.
* Some skills are built-in (search the web, generate an image, render a chart). Others are custom skills your organization uploads.

See: xref:../06-skills/01-overview.adoc[Skills overview].

== Tool

A *tool* is a single concrete action — for example, "search the Web," "interpret files," or "generate images." A tool is what actually executes when an agent decides to act.

⚠️ Confirm your tool definition with [feature owner]. The placeholder framing used here: tools are the executable units inside skills.

== Connector

A *connector* is the integration to an external system (Google Workspace, GitHub, Slack, Salesforce, or a custom MCP server). The connector handles authentication, data access, and which connector-specific tools that app exposes.

⚠️ Confirm your connector definition with [feature owner]. The placeholder framing used here: connectors are the integration layer; the tools an agent uses are surfaced through connectors.

See: xref:../03-connectors/01-overview.adoc[Connectors overview].

== Data source

A specific data location an agent can read — files, ThoughtSpot Models, a Google Drive folder, or a set of uploaded files.

== Memory

Memory lets agents and workflows remember information across sessions — user preferences, organizational facts, recurring rules. Without memory, every conversation starts from scratch. Memory is scoped (per user, per agent, per organization) so a personal note doesn't leak into a colleague's context, and agent and workflow runs become more accurate and valuable for each AgentSpot user over time.

See: xref:../04-memory/01-overview.adoc[Memory overview].

== Session

A *session* is a single conversation with an agent. Within a session, the agent remembers earlier messages. Starting a new session resets the conversational context (but not long-term memory).

== Role

The permission level a user holds in AgentSpot. Typical roles:

* *AgentSpot Admin* — tenant configuration.
* *Agent Builder* — create, edit, publish agents and workflows.
* *Agent Consumer* — use published agents.

⚠️ Confirm the exact role names with [feature owner].

== Audit log

A tenant-wide record of who did what and when — sign-ins, agent runs, data-source reads, configuration changes. Used for security review and troubleshooting.
