== What this connector surfaces

⚠️ Confirm the full tool list. Typical tools:

* *Records* — get by id, list by object, create, update, delete (gated), upsert.
* *Search* — SOSL across multiple objects.
* *Query* — SOQL with bind parameters.
* *Describe* — object metadata, fields, picklist values (essential for letting an agent reason about your schema).
* *Files / Attachments* — upload, list, download.
* *Approvals* — submit for approval, approve, reject.
* *Bulk API* — for large reads or writes (separate, slower path).

== Authentication

[cols="1,2",options="header"]
|===
|Pattern |When to use

|*OAuth — connected app (JWT bearer)*
|Server-to-server identity; predictable; no user prompt. Good for tenant-wide agent automation.

|*OAuth — user pass-through*
|Each user grants consent. Actions show under the user's name. Required when audit needs personal attribution.

|*Username + password + security token*
|Avoid. Legacy; brittle.
|===

⚠️ Confirm preferred pattern with [feature owner].

== Setup (admin)

. In Salesforce: create a *Connected App* with the OAuth scopes you'll grant AgentSpot.
. Configure IP restrictions and refresh policy according to your security baseline.
. In AgentSpot: *Admin* > *Connectors* > *Add connector* > *Salesforce*.
. Enter the Connected App's consumer key and (for JWT) upload the certificate; or complete the OAuth flow with an admin account.
. Review and approve scopes.
. Choose allowed groups.
. (Optional) Restrict to specific objects — e.g. allow `Account`, `Opportunity`, `Lead` but block `User`, `PermissionSet`.
. Test by running a small SOQL query (`SELECT Id, Name FROM Account LIMIT 1`).

*Expected result:* Status *Connected*; allowed groups see Salesforce tools in builders.

== Scopes

⚠️ Confirm exact scopes. Typical Connected App scopes:

* `api` — access standard API; required.
* `refresh_token, offline_access` — long-lived sessions; required for unattended workflows.
* `chatter_api` — Chatter posts (only if used).
* `wave_api` — Tableau CRM (only if used).
* `full` — full access; avoid unless absolutely necessary.

Best practice: use field-level security and object permissions inside Salesforce to scope what the OAuth identity can do, not just OAuth scopes. Salesforce's permission model is more granular than the OAuth scope set.

== Common patterns

* *Pipeline Q&A* — agent answers natural-language questions over Opportunities; uses *Describe* once at agent build time to learn the schema, *Query* per question to fetch data.
* *Lead triage* — workflow on `Lead.created` event; agent scores the lead, updates Lead with score and rationale, routes via assignment rules.
* *Account research* — user mentions an Account in chat; agent fetches related records (opportunities, cases, contacts) and produces a one-page summary.
* *Stale-deal nudge* — workflow runs weekly; finds opportunities not updated in 30 days; posts a Slack reminder to each owner with the deal context.
* *Forecast narrative* — workflow gathers pipeline and forecast snapshots; agent writes a narrative for the sales leadership Slack channel.

== Limits

⚠️ Confirm specific limits with [feature owner] and Salesforce's documentation. Watch for:

* Daily API call quota per org (varies by edition).
* SOQL row limits per query (50,000 default) and selectivity rules.
* Bulk API job count and processing limits.
* Field-level security rules — the agent only sees fields the identity has access to.
* Governor limits if the connector uses Apex on the Salesforce side.

== Privacy

* Salesforce data sent to the underlying model is governed by your model provider's data-handling terms. Confirm before enabling Q&A use cases on Lead or Contact PII.
* Restrict object access through Salesforce permission sets — don't rely on AgentSpot allow-lists alone.
* Audit log captures both AgentSpot's call and Salesforce's record-level audit; cross-reference both when investigating.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|"INVALID_SESSION_ID" mid-workflow.
|Token refresh failed — common when the user's password changed. Reauthorize the connector.

|SOQL returns 0 rows for a query you can run in Workbench.
|The OAuth identity lacks field-level security on a referenced field, or the WHERE clause references a field it can't see. Check the FLS in Salesforce.

|"REQUEST_LIMIT_EXCEEDED".
|Daily API quota hit. Reduce poll frequency, batch queries, or talk to your Salesforce admin about upping the quota.

|Create succeeds but workflow can't read the new id.
|Capture the returned id in the *Call tool* step's output and reference it explicitly in downstream steps.

|Picklist value updates fail.
|Inactive picklist values cannot be set. Reactivate the value or update the workflow to use an active one.
|===
