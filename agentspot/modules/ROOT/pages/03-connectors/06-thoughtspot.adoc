[.lead]
ThoughtSpot is AgentSpot's parent platform. The ThoughtSpot connector is connected by default for any AgentSpot tenant — it surfaces your Worksheets, Models, Liveboards, and Spotter analytics so agents can reason over the data you've already curated.

[NOTE]

== Why ThoughtSpot is first-class

Most of your data work in ThoughtSpot already encodes business meaning — joins, derived columns, business-friendly column names, row-level security. Agents that read raw warehouse tables have to rediscover all of that. Agents that read ThoughtSpot Worksheets and Models inherit it.

A Worksheet labeled `EMEA Open Pipeline` with curated columns is a far better data source for an agent than a raw `salesforce.opportunity` table.

== What this connector surfaces

⚠️ Confirm the full tool list. Typical tools:

* *Worksheets and Models* — list, get metadata, query (with filters, group-bys, aggregations).
* *Liveboards* — list, get metadata, get visualization data, render to image.
* *Spotter (NL → analytics)* — ask a natural-language analytical question, get a structured result with chart spec.
* *Search* — search across Liveboards, Worksheets, Models by name and tag.
* *Permissions* — check what the current user can see.

== Authentication

ThoughtSpot inherits your tenant's existing identity model. There's no separate OAuth flow — the connector authenticates to your ThoughtSpot tenant using the same SSO and roles your users already have.

⚠️ Confirm whether the connector acts as the user (pass-through) or as a service identity. Default: pass-through, so row-level security applies per user.

== Setup (admin)

For most tenants this is *already done* — the ThoughtSpot connector is connected automatically when AgentSpot is provisioned.

If you need to verify or reconnect:

. Open *Admin* > *Connectors* > *ThoughtSpot*.
. Confirm status is *Connected* and the tenant URL is correct.
. (Optional) Restrict the tool surface — e.g. disable image rendering or Spotter handoff for specific groups.
. (Optional) Restrict by Worksheet/Model tag — agents can only query data sources matching the allowed tags.

*Expected result:* All AgentSpot groups can see ThoughtSpot tools in the agent and workflow builders.

== Common patterns

* *Worksheet-grounded Q&A* — agent has 1–3 ThoughtSpot Worksheets attached and answers business questions over them with citations to the Worksheet name.
* *Liveboard summariser* — workflow runs weekly; fetches data from a curated Liveboard; an agent writes a narrative summary; the narrative plus a rendered image are sent to a Slack channel.
* *Spotter handoff* — when a user asks an open-ended analytical question, the agent calls Spotter, gets the chart spec back, and presents the answer with the chart embedded.
* *Drill-down assistant* — user sees a number on a Liveboard; clicks "Ask Agent"; the agent has the row context and answers follow-up questions about that slice.

== Row-level security and permissions

The ThoughtSpot connector defaults to *pass-through* identity: the agent sees what the current user can see — no more, no less.

Implication for builders:

* If you publish an agent to group X, members of group X who have access to the Worksheet see one set of rows; members who don't have access see fewer (or none). The agent's answers will differ accordingly.
* This is the right behaviour. Don't try to use a service identity to bypass it without a clear governance reason.

⚠️ Confirm the connector's identity behaviour with [feature owner], including any service-identity option for tenant-wide workflows.

== Limits

⚠️ Confirm specific limits with [feature owner]. Watch for:

* Query result-size limits (rows returned in one call).
* Concurrent query limits per user.
* Spotter rate limits if used at high frequency.

== Common patterns to avoid

* *Don't query raw warehouse tables when a curated Worksheet exists.* Worksheets are why ThoughtSpot is a better starting point than raw SQL.
* *Don't attach 20 Worksheets to one agent.* Agents lose accuracy when the data surface is too broad. Build a focused agent per domain.
* *Don't try to bypass row-level security.* If a user shouldn't see the data on a Liveboard, they shouldn't see it through an agent either.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|Connector status shows "Disconnected" after the tenant was provisioned.
|Verify the tenant URL in *Admin* > *Connectors* > ThoughtSpot. Reconnect if it changed.

|Agent answers "I don't have access to that Worksheet."
|Confirm the user has Worksheet-level access in ThoughtSpot. AgentSpot inherits ThoughtSpot's permissions.

|Spotter handoff returns no result.
|The natural-language question may be out of scope for the connected Model/Worksheet. Rephrase or attach a broader data source.

|Liveboard image render is blank.
|Liveboard may require parameters not provided by the workflow step. Open the Liveboard in ThoughtSpot to see required parameters.

|Different users get different answers to the same question.
|Expected — row-level security is per user. If the variance is unwanted, talk to your ThoughtSpot admin about adjusting access at the Worksheet level.
|===
