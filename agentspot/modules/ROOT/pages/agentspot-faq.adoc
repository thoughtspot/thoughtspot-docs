== Connectors

[.faq]
--
Can we add the [X] MCP connector?::
If the tool has an MCP Server, an AgentSpot admin can add it.
If the tool does not have an MCP Server, Please fill a connector request https://community.thoughtspot.com/s/login/?ec=302&startURL=%2Fs%2Fideas[here^].

My agent does not connect to <connector xyz>::
Ensure that
. You have signed in to the connector by doing the following:
.. Click your user menu in the upper-right corner of AgentSpot
.. Click *Connectors*.
.. Find your connector, click *Connect* and sign in.
your agent has been configured to access that connector (Agent > Edit > Connector > select connector <xyz>
. Your agent has been configured to access that connector, by doing the following:
. Open your agent, click *Edit agent*, then click the pencil icon next to Connectors.
. Select a connector and click Save changes.

== Building agents

[.faq]
--
I gave the agent instructions or corrections during a conversation, but they're gone the next time I open the agent. Why?::
Conversations are “use mode”: instructions you type there are not saved to the agent's configuration. They only apply to that session, or can update the agent or user memory.
+
To make a change permanent, go to Edit mode (the builder) and update the Instructions there. A quick way: tell the agent in the builder what you want to change and it will update the instructions for you.
+
TIP: If you catch yourself correcting the agent in use mode, copy that correction and paste it as a builder edit to make it stick.
--

== Using agents

[.faq]
--
Can I duplicate an existing agent to use as a starting point for my own?::
Agent copy ("Save as") is not yet supported, but it's on the roadmap. In the meantime: open the agent you want to base yours on, read its instructions in the builder, create a new agent, and paste those instructions as a starting point. If the agent owner shares the instructions with you directly, that's the fastest path.

I built an agent. How do I put it on a schedule?::
Agents can't be directly scheduled: that's what Workflows are for. The fastest way to convert an existing agent:

. In a chat with your agent, ask: "Create instructions for me to build a workflow in AgentSpot that runs this agent's task on a [daily/weekly/etc.] schedule."
. Copy the instructions it produces.
. Create a new Workflow in AgentSpot and paste those instructions to guide the workflow builder.
+
NOTE: you cannot invoke an existing agent directly inside a workflow today — the workflow must contain its own instructions.

Can I expose my AgentSpot agent as a Slack bot so users can interact with it without opening AgentSpot?::
Yes: Slack integration is live for public channels. Here's how to install it:

. Build your agent in AgentSpot as normal.
. Invite AgentSpot to the public channel you’d like to interact with this agent in. You can do that by simply typing “@AgentSpot” in that Slack channel.
. Ask an AgentSpot admin to bind your agent to that specific Slack public channel. This will ensure that questions addressed to @AgentSpot in that channel are answered by the agent of your choice.

Users can then @AgentSpot in that channel to interact with your agent.

NOTE: Access rules carry over: only users who already have access to the agent in AgentSpot can use it via Slack.

Currently not supported: direct messages and private channels. Slash (/) command bridges (For example: /nda-review) are also not yet supported.

How do I share an agent with my teammates?::
Open the agent → click Share → enter colleague email addresses. There are no groups in AgentSpot today: you must share individually with each person. Users you share with will receive an email notification.

== Workflows

[.faq]
--
When should I use an agent, when should I use a workflow?::
Use agents to have live conversations and iterate. Use workflows whenever you want to schedule tasks.

You cannot invoke an existing agent in a workflow, but you can go to that agent and tell it you want to create a repeatable workflow out of what it's doing, and then paste its instructions in the workflow creator.

I'm having trouble with workflows — scheduling, viewing step details, editing inputs, or the chat is greyed out.::
Editing inputs directly: Intentionally restricted right now — each step's output must lock-step into the next step's input, so the workflow builder agent controls inputs holistically. Change inputs by chatting with the builder.

Can users see intermediate workflow outputs?::
Not fully today. Some input/output JSON exists, but meaningful intermediate visibility in the builder is still being worked on.
--

== Apps

[.faq]
--
Publishing and sharing an App::
Once the agent builds an App and is shown in preview, you can choose to publish those changes so they’re saved. Note that publishing an App will only allow view access for people you’ve explicitly ‘Shared’ the App with. So essentially the first time you’ve hit publish, no one else besides the creator is seeing the App unless it's explicitly shared with others.

How does access control work?::
Every App inherits the access rules on your sources. ThoughtSpot Models honor your cluster's row-level security and permissions (currently Champagne). Unstructured connectors (Salesforce, Slack, Jira, Google Workspace) authenticate per user via OAuth. Two users opening the same App see two different, correctly-scoped versions.

What kinds of blocks can be inside an App?::
Apps combine data nodes (charts, KPIs, tables fetched live from your sources) and agent nodes (LLM-generated summary blocks that interpret the data). The agent picks which block types fit the prompt.

Which connectors are supported?::
AgentSpot shares connectors across Agents, Workflows and Apps. Some connectors are in progress; check with the AgentSpot team on #agentspot-champs for the current stable list.

Can I edit an App after it's built?::
Yes. Every App can be re-opened in the builder. Chat with the agent to add sections, change styles, adjust scope, or fix issues.

Are Apps available only in AgentSpot?::
Yes, for now Apps are only in AgentSpot and they can connect to ThoughtSpot models. A future edition will provide a path for Apps from existing ThoughtSpot dashboard workflows.

How can I use CSV data to create apps?::
As of now, we cannot do this directly. An easy and scalable way is to upload it to Google Sheets and use Google Drive connector to fetch the data.

== Admin center

[.faq]
--
I've had AgentSpot enabled on my cluster but I can't find where to grant users access or the AgentSpot link isn't showing in the nav.::

AgentSpot roles should appear in Admin > Roles in ThoughtSpot. Assign the relevant role to your users there.

AgentSpot can't be accessed via SSO on my cluster. Do users need separate accounts?::
SSO for AgentSpot is not yet supported on all cluster configurations. On affected clusters, users will need to log in with basic authentication. Contact support if you need help setting this up.

What does an agent "user" mean in the admin usage dashboard? - Is it people who have added the agent to their team or had a conversation? Does having a conversation add it to a team by default?::

It represents the total number of users who had a conversation with the agent. They need not have saved it to their team to be counted there.

== Guardrails and permissions

[.faq]
--
Are guardrails only instruction-based today?::
Beyond instructions, admins can configure tool-level permissions per connector in staging---for example, disabling Jira ticket creation. This is intended to prevent destructive actions caused by hallucinations.

Can permissions be controlled granularly?::
Yes. Controls apply to every tool within every connection.

Can admins assign credit limits per user?::
Not today. It is on the roadmap, but not near-term.
--
