= Uploads and attachments
:last_updated: June 10, 2026

[.lead]
Upload files to an agent so it can read, summarize, and answer questions about their contents — within a single conversation.

== Who uploads what

There are two distinct upload paths. Don't confuse them.

[cols="1,2",options="header"]
|===
|Path |What it's for

|*Builder upload (at agent design time)*
|A builder attaches a file as a permanent data source on the agent. Every user sees it.

|*End-user upload (in a conversation)*
|An end user drops a file into a single conversation. Only that conversation sees it; it's gone when the session ends.
|===

This article covers end-user uploads. For builder-managed data sources, see xref:02-create-an-agent.adoc[Create an agent, Step 4].

== Supported file types

⚠️ Confirm the full supported-type list with [feature owner]. Common types typically supported:

* *Documents* — PDF, DOCX, TXT, MD.
* *Spreadsheets and tabular* — CSV, TSV, XLSX.
* *Images* — PNG, JPG (read as image; agent may extract text via OCR).
* *Code and data* — JSON, YAML, source code text files.

Unsupported types are rejected at upload with an error.

== How to upload in a conversation

. Open a conversation with the agent.
. Select the attach icon in the message box (paperclip, ⚠️ confirm).
. Choose one or more files.
. Wait for the file(s) to show *Ready*.
. Ask your question. Reference the file by name if you uploaded more than one ("In `policy-v3.pdf`, what's the data retention period?").

*Expected result:* The agent's answer references the uploaded file's contents and (if citations are on) cites the file by name.

== How agents use uploaded files

The agent reads the file once and uses its contents as context for the rest of the session. For large files the agent indexes the file and retrieves only the relevant sections per question — you don't need to chunk it yourself.

For tabular files (CSV, XLSX), the agent treats the file as data, not prose: it can filter, aggregate, and chart the rows rather than reading them line by line.

⚠️ Confirm the index/retrieval behavior with [feature owner].

== Limits

* *Per-file size* — large files are subject to a maximum size. ⚠️ Confirm the limit.
* *Per-session total* — there's a cap on total uploaded bytes per conversation. ⚠️ Confirm.
* *File count* — there's a cap on number of files in one conversation. ⚠️ Confirm.
* *Session lifetime* — uploaded files are kept for the session only and removed when the session is archived. ⚠️ Confirm retention behavior.

== Privacy

* Files you upload in a conversation are visible to you, the agent, and (if your organization has enabled conversation content logging) to your admin. ⚠️ Confirm.
* Files are not used to train the underlying model. ⚠️ Confirm with your model provider's documentation.
* Do not upload secrets, credentials, or files that contain regulated personal data unless your organization has approved the agent for that data class.

== Best practices

For end users:

* Upload the smallest file that contains the answer. A 300-page PDF works, but a 5-page excerpt is faster and more accurate.
* Name files clearly. The agent uses filenames in its answers.
* For tabular data, include a header row.
* For long documents, ask scoped questions ("what does section 4.2 say about X") rather than open-ended ones ("summarize this document").

For builders:

* If end users repeatedly upload the same file, attach it as a builder data source instead. See xref:02-create-an-agent.adoc[Create an agent].
* In your instructions, tell the agent how to behave when a file is attached vs not attached. Example: "If the user has uploaded a document, answer only from that document. If no document is attached, answer from your connected data sources."
* Set expectations in the agent's *Short description* about what types of files it handles well.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|Upload fails with "unsupported file type."
|Convert to a supported type (e.g. export DOC as DOCX or PDF).

|File uploads but the agent says it can't read it.
|The file may be a scanned image-only PDF without OCR. Re-export as a text-based PDF, or upload the text directly.

|Agent answers from general knowledge instead of the file.
|Reference the file by name in your question. If it still ignores it, add to the agent's instructions: "When a file is attached, answer only from the file."

|Upload is slow.
|Large files take time to index. Wait for *Ready* before asking.

|File disappears between sessions.
|Expected. End-user uploads are session-scoped. Ask your builder to attach it as a permanent data source if you need it across sessions.
|===
