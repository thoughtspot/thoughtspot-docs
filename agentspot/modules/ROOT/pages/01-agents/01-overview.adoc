= Agents Overview
:doctype: book
:icons: font

[.lead]
Agents are focused, conversational assistants that answer questions or perform tasks for a defined audience, grounded in your organization's data.

== What an agent is

An agent has four parts:

* *Instructions* — a system prompt that defines who the agent is, what it should and shouldn't do, how it should respond, and what to do when unsure. The most important part.
* *Data* — the data sources the agent can read. Without attached data, the agent only has its model's general knowledge.
* *Skills and tools* — optional. Skills give the agent the ability to act (post a Slack message, create a Jira issue, run a query) rather than only answer.
* *Settings* — model choice, response controls, citations, and other runtime configuration.

== When to build an agent

Build an agent when:

* The same kind of question gets asked over and over.
* Users need a self-serve answer instead of waiting for an analyst or SME.
* The question requires reasoning across data plus context (not just a chart).
* You want a consistent tone and scope across many users.

Don't build an agent when:

* A single dashboard or saved query would do the job better.
* The task is one-off — write it as a doc instead.
* The work is a fixed multi-step process with no user conversation in the middle. Use a xref:../02-workflows/01-overview.adoc[workflow] instead.

== Agent vs workflow at a glance

[cols="1,1,1",options="header"]
|===
|Dimension |Agent |Workflow

|Trigger
|A user asks a question.
|A schedule, event, manual run, or API call.

|Shape
|Conversational. Open-ended.
|Linear or branching. Repeatable.

|Human in the loop
|Always — the user is in the conversation.
|Optional — only at explicit approval steps.

|Best for
|Q&A, drafting, lookups, exploration.
|Digests, triage, scheduled reports, multi-step automation.
|===

You can also call agents from inside workflows — that's how you get the best of both.

== The agent lifecycle

. *Plan* — name, audience, job, scope, data needed.
. *Build* — write instructions, attach data, configure settings.
. *Test* — run real questions in the preview panel; include adversarial ones.
. *Publish* — release to a small group with release notes.
. *Use* — your audience asks questions and gives feedback.
. *Iterate* — review feedback monthly; publish new versions as the job evolves.

== Roles

* *Agent Builder* — creates, edits, publishes agents.
* *Agent Consumer* — uses published agents.
* *AgentSpot Admin* — controls which data sources and model providers are available and to whom.
