= Sharing and Publishing
:doctype: book
:toc: left
:toclevels: 2
:icons: font
:experimental:

[.lead]
Move an agent from private draft to a published version your team can find and use — and manage versions, audiences, and rollbacks over time.

== Publishing model in one diagram

----
Draft  ──►  Publish v1  ──►  Use  ──►  Edit (draft again)  ──►  Publish v2
                │                                                   │
                ▼                                                   ▼
            Audience sees v1                              Audience sees v2
----

Editing an agent always creates an unpublished *draft*. The published version remains live for your audience until you publish a new one. You can roll back to an earlier version at any time.

== Audiences

When you publish, you pick who can see and use the agent.

[cols="1,2",options="header"]
|===
|Audience |Use when

|*Private*
|Only you can use it. Good for ongoing iteration and personal-use agents.

|*Group*
|One or more groups (mapped from your IdP or created by your admin). The default for production agents.

|*Organization*
|Everyone with AgentSpot access in your tenant. Use sparingly — only for agents that are genuinely org-wide.
|===

You can pick multiple groups. Group membership is evaluated at sign-in; removing a user from a group revokes their access at their next sign-in. ⚠️ Confirm propagation timing with [feature owner].

== Publish for the first time

. From the agent editor, select *Publish*. ⚠️ Confirm label.
. Pick the audience.
. Add *Release notes* — one or two sentences on what the agent does. These show in the agent's detail page and version history.
. Publish.

*Expected result:* The agent appears in the consumer agent list for the chosen audience, and version `v1` is recorded.

== Publish a new version

. Edit the agent — instructions, data, skills, or settings.
. Test in the preview panel.
. Select *Publish*.
. Add release notes describing what changed and why.
. Publish.

*Expected result:* The new version becomes the live version. Users in active conversations finish on the previous version; new conversations start on the new version. ⚠️ Confirm cutover behavior with [feature owner].

== Version history

. Open the agent > *Versions*. ⚠️ Confirm navigation.
. Each entry shows the version number, who published it, when, and the release notes.
. Select a version to see the instructions, data, and settings as published.

== Roll back

. In *Versions*, select the version you want to roll back to.
. Select *Make live* (or *Restore*). ⚠️ Confirm label.
. Add a short note explaining the rollback.

*Expected result:* The selected version becomes live. AgentSpot records the rollback as a new version entry — original versions are never deleted.

== Compare versions

. In *Versions*, select two versions and choose *Compare*. ⚠️ Confirm feature availability.
. AgentSpot highlights changes to instructions, attached data sources, skills, and settings side by side.

Use compare before publishing a new version to confirm your edits are scoped to what you intended.

== Sharing without publishing

There are three different "share" actions — easy to confuse:

[cols="1,2",options="header"]
|===
|Action |What it does

|*Publish*
|Makes the agent available to its audience via the *Agents* list.

|*Share agent link*
|Sends a direct link to the agent so a colleague can open it without browsing. They still need access via the audience.

|*Share conversation link*
|Sends a link to one specific conversation. See xref:04-sessions-and-conversations.adoc[Sessions and conversations].
|===

Sharing a link never grants access by itself — the recipient must already be in the agent's audience.

== Unpublish or delete

* *Unpublish* — removes the agent from the audience's list but keeps all versions in your editor. You can republish later.
* *Delete* — removes the agent and all its versions. Conversation history may or may not be retained depending on tenant policy. ⚠️ Confirm with [feature owner].

Unpublish first. Only delete when you're sure the agent is no longer needed.

== Best practices

* *Publish small, publish often.* A new version per week is healthier than a new version per quarter.
* *Release notes matter.* They help your audience understand what changed and give you (and your admin) a paper trail when behavior shifts.
* *Promote in stages.* Private → small group → wider group → organization. Each stage is a chance to catch problems cheaply.
* *Pin a deprecation date* in release notes when you're about to replace an agent, so users have time to switch.
* *Don't reuse one agent for two jobs.* If you find yourself adding scope across publishes, split into two agents instead.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|Publish button is greyed out.
|You haven't saved your latest changes, or you don't have publish permission on this agent. Confirm with the agent owner.

|New version published but users still see the old behavior.
|Ask them to start a *New conversation*. Active conversations may finish on the previous version.

|Group you want to publish to doesn't appear.
|The group hasn't been created or shared with you. Ask your admin.

|Rolled back to v3 but the agent is still showing v5 behavior.
|Confirm the rollback completed (a new version entry should appear). Start a new conversation to pick up the rolled-back version.
|===
