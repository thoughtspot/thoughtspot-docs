Build, test, and share your first AgentSpot agent end-to-end.

== Overview

This guide is the full builder walkthrough. Deeper topics — writing instructions, managing sessions, file uploads, and sharing — have their own articles linked at each step.

By the end you'll have a shared, tested agent your team can use.

== Prerequisites
* You have connected to one or more connectors. While not mandatory, connectors provide more context to your agents and help them act for you, making your agent more valuable.
* You can answer in one sentence: "What job will this agent do, for whom?"
* (Recommended) You have 3–5 example questions a real user would ask.

== Step 1: Plan the agent

Write these down before opening the builder. Vague agents do not get used.

* *Name* — short and recognizable (e.g. `EMEA Pipeline Assistant`).
* *Audience* — which team or group.
* *Job* — one sentence.
* *Out of scope* — what it explicitly will not do.
* *Data it needs* — specific sources, tables, or worksheets.
* *Skills it needs* — usually none for a first agent.

=== The "DNA" of an Agent
* **Instructions:** The "brain" of the agent. Defines persona, mission, and response rules.
* **Skills:** Reusable "how-to" knowledge (e.g., "How to format a deck using the company PowerPoint template").
* **Tools:** Functional capabilities like web search, code interpretation, or the ability to ask clarifying questions.
* **Knowledge (Files & Models):** Upload PDFs/FAQs or connect to ThoughtSpot structured data models.
* **Connectors:** Enables the agent to take action. For example, a **Jira Connector** allows the agent to read tickets and write new bug reports.
* **Starter Prompts:** The suggested questions (bubbles) shown to users at the start of a chat.

== Step 2: Create a new agent

. On the AgentSpot home page, click *Create new agent*.
. Start chatting with the agent builder. It is best to start with a well-formed prompt (see below) but notice that AgentSpot will ask you clarifying questions to come up with a good set of instructions for the agent.
. Optionally, you can edit any section of the agent's definition by accessing it from the side menu.
. Once you are satisfied with the agent, click *Save*.

TIP: We recommend you save the agent and try a few conversations. As you see how the agent behaves through chats, you can then go back to the agent _Edit_ mode and give it feedback on how to improve, improving your agent's behavior iteratively.

*Expected result:* The agent editor opens with empty *Instructions*, *Data*, *Skills*, and *Settings* tabs. #⚠️ Confirm tab names#.

== Step 3: Share

Powerful agents should be shared! Sharing agents allows others in your organization to leverage the skillset of your agent, and prevents “AI silos”, where every contributor creates similar agents that won't all behave in the exact same way, potentially creating confusion in the organization.

. Select *Share*.
. Choose who you want to share the agent with (you can also share it with everyone in the company with access to AgentSpot).
. Choose access for each user (edit vs use only).
. Share.

*Expected result:* The agent appears in the consumer agent list for the chosen audience, and a new version is recorded.

.How to write effective agent creation prompts
[IMPORTANT]
====
AgentSpot does a great job at disambiguating user intent to create bounded and trustworthy agents, but providing clear prompts to the agent builder will go a long way in making that agent behave as you expected.

A good prompt must contain:

* An objective: Express what you want the agent to do.
* Connectors
* Expected output

Optionally, this information will help as well:

* Examples: AI Agents learn most by understanding what good looks like. Provide examples of your past work that you'd like that agent to do for you. That'll allow it to better understand format, tone, expected output in a way that may be strenuous to explain step by step.

* Audience: Telling the agent who the target audience is will help it fine tune tone, length & complexity of the response, etc.
====

== Connecting applications
To provide value, agents require context and the ability to act. If an agent requires external data (e.g., from Notion or Salesforce), you will be prompted to connect.

1. **Identify requirements:** The agent interface will flag if an app is not yet connected.
2. **Authenticate:** Click the **Connect** button.
3. **Authorize:** Complete the OAuth flow in the pop-up window to grant AgentSpot permission.
4. **Active state:** Once connected, the agent can perform deep-context searches and execute tasks (like creating tickets or updating records).

== Managing your agents
When you find a useful agent in the library, you must decide how to keep it:

[cols="1,2,2", options="header"]
|===
| Action | Description | Best For...
| **Save to Team** | Bookmarks the organizational agent. | Standard users who want the latest updates/improvements from admins.
| **Make a Copy** | Creates a private "branch" of the agent. | Power users who want to modify instructions or add private connectors.
|===

== Using Your Agents
Once set up, your agents are available in your sidebar.

* **Chat History:** Resume any previous conversation from the left-hand panel.
* **Search & Filter:** Use the **List View** to find specific agents by category, such as "Marketing" or "HR."
* **Contextual Actions:** Remember that agents with connectors (like Jira or Slack) can perform "last mile" tasks for you, such as drafting and sending messages or filing tickets.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|"I don't have access to that data."
|Confirm the data source is attached and that your admin shared it with your group.

|Confident but wrong answers.
|Tighten instructions ("only answer from attached data"), lower temperature, add per-table data descriptions.

|Formatting instructions are ignored.
|Move formatting to the top of the prompt; shorten the overall instructions.

|Agent answers out-of-scope questions.
|Add an explicit *What not to do* section naming the topics and re-test.

|Citations missing.
|Confirm *Citations* is on in *Settings* and that the source supports citations. ⚠️ Confirm per-source citation support.
|===
