[.lead]
Set per-user, per-group, and per-tool quotas; review tenant usage; configure governance defaults; manage audit logging.

== Why usage controls exist

Three real risks AgentSpot quotas mitigate:

* *Cost runaway.* One badly-instructed agent in a loop can burn through model spend.
* *External rate-limit hits.* A workflow that hammers a downstream API will exhaust your quota with that vendor.
* *Misuse.* Quotas put a ceiling on what any one user (or compromised account) can do in a day.

Sensible defaults at the tenant level are better than aggressive limits per agent — most agents stay well under any reasonable cap.

== What you can limit

⚠️ Confirm the complete list of quota dimensions with [feature owner]. Typical:

[cols="1,2,1",options="header"]
|===
|Dimension |Description |Where it applies

|*Model tokens per user per day*
|Total LLM tokens consumed by one user in 24 hours.
|Per user

|*Model tokens per group per day*
|Same, summed across a group.
|Per group

|*Agent runs per user per day*
|How many times a user can invoke any agent.
|Per user

|*Workflow runs per workflow per day*
|How many times a single workflow can execute.
|Per workflow

|*Concurrent workflow runs*
|How many runs of one workflow can be in flight at once.
|Per workflow

|*Connector tool calls per user per day*
|External tool invocations through a connector.
|Per user, per connector

|*Custom skill calls per user per day*
|Same, for custom skills.
|Per user, per skill

|*File upload bytes per user per day*
|Total bytes uploaded into agent sessions.
|Per user
|===

== Set tenant defaults

. Open *Admin* > *Governance* > *Quotas*. ⚠️ Confirm path.
. For each dimension, set a default value that applies to all users / groups / workflows unless overridden.
. Choose the behaviour on limit hit:
+
* *Block* — refuse further calls until the window resets.
* *Notify admin and continue* — alert but don't block.
* *Notify user and block* — what most production tenants want; the user sees a friendly explanation.
. Save.

Start generous. Tighten once you see real usage patterns.

== Override per group, agent, or workflow

Defaults catch the common case. Overrides catch the exceptions.

* *Per group:* a *Premium Builders* group gets 5x the model-token default.
* *Per agent:* a high-traffic customer-facing agent gets a higher per-day cap.
* *Per workflow:* a long-running batch workflow gets a higher concurrent-runs limit.

Each override has the same shape as the default — same dimensions, different numbers.

⚠️ Confirm the override surface and precedence rules with [feature owner].

== Guardrails

Guardrails block content categories rather than limiting volume.

. Open *Admin* > *Governance* > *Guardrails*. ⚠️ Confirm path.
. Enable categories you want filtered (e.g. personal data, regulated financial advice, code execution, prompt-injection attempts). ⚠️ Confirm available categories.
. Per category, choose: *Block*, *Warn*, or *Off*.
. Apply guardrails to *user inputs* (incoming messages), *model outputs* (agent responses), or both.
. Save.

Guardrails are tenant-wide defaults. Specific agents or workflows can request stricter settings; they cannot loosen the tenant defaults.

== Data egress controls

. Open *Admin* > *Governance* > *Data egress*. ⚠️ Confirm path.
. Choose whether agents are allowed to call external tools (web search, outbound webhooks, third-party APIs not behind a connector).
. If allowed, restrict to an explicit allowlist of domains.

Egress controls exist because once an agent calls an arbitrary URL, you've delegated trust to whatever is on the other end. Be conservative.

== Audit logging

. Open *Admin* > *Governance* > *Audit*. ⚠️ Confirm path.
. Enable logging for the event types you need:
+
* Sign-in (success and failure)
* Agent creation, edit, publish, delete
* Agent execution (per run)
* Workflow creation, execution, completion
* Connector configuration changes
* Tool calls (per call, with caller, target, inputs/outputs)
* Guardrail triggers
* Quota exhaustion
* Memory save / delete
* Admin actions
+
⚠️ Confirm full event-type list.
. Configure export to your SIEM (Splunk, Datadog, S3, etc.) via the audit export endpoint. ⚠️ Confirm supported destinations.
. Set the retention period in days. Defaults: ⚠️ Confirm.

Treat audit as a critical system. Confirm export reliability with a regular test event.

== Usage reporting

The *Admin* > *Usage* page (⚠️ confirm path) gives you tenant-level reporting:

* *Headline metrics* — active users, agents in use, workflow runs, model tokens consumed, this period.
* *Trend charts* — usage over time so you can spot drift.
* *Top consumers* — users, agents, workflows ranked by token spend and tool calls.
* *Failures* — recent failed runs and guardrail blocks, grouped by cause.

Use this weekly:

* Look for *new* top consumers — a sudden #1 spot usually means a misconfigured agent.
* Look for *failure clusters* — three identical failures on the same step is a real bug.
* Look for *guardrail trend* — rising blocks may indicate either misuse or an over-aggressive guardrail.

== Per-user usage visibility

Users typically don't see their own quota counters by default. ⚠️ Confirm visibility behaviour.

Best practice:

* Enable per-user visibility so users can self-diagnose "why is the agent blocking me?"
* Pair with a clear error message when a user hits a quota: "You've used 95% of your daily model-token quota. Limit resets at midnight UTC."

== Best practices

* *Start generous, tighten on data.* Aggressive defaults make builders feel constrained and discourage adoption.
* *Watch the top-N daily.* The *Usage* page surfaces problems before they hit tickets.
* *Quota + audit together.* A quota without audit visibility is just a wall. Audit without a quota is just a story.
* *Set workflow concurrent-run caps* for any workflow triggered by external events. Bursty triggers can otherwise spawn dozens of parallel runs.
* *Document the rationale* for each non-default quota override. Future-you will not remember why `Sales-EMEA` had 5x the default cap.

== Troubleshooting

[cols="1,2",options="header"]
|===
|Symptom |What to try

|Users complain agents stopped working at the same time of day.
|Likely a per-user or per-group daily quota. Confirm in *Admin* > *Governance* > *Quotas*.

|Workflow runs are blocked unexpectedly.
|Open the run log — the audit entry shows which guardrail or quota triggered the block.

|Audit events are missing in your SIEM.
|Confirm the export endpoint is configured and credentials haven't expired. Re-run the *Test export* button.

|Guardrail blocking valid business content.
|Either narrow the guardrail category or move from *Block* to *Warn* while you investigate.

|Usage page shows zero data.
|Audit logging may be disabled. Enable in *Audit* settings.
|===
