== Provisioning checklist

For a brand-new tenant, work through these in order. Each links to the right article for depth.

. *Confirm entitlement.* In *Admin* > *Subscription* (⚠️ confirm path), check that AgentSpot is listed with the seat count and edition you expect. If it's not, contact your ThoughtSpot account team.
. *Enable the feature.* In *Admin* > *Features* > *AgentSpot*, toggle on. ⚠️ Confirm path. Wait for provisioning to complete (typically a few minutes; ⚠️ confirm).
. *Add a second admin.* Never leave the tenant dependent on a single admin account. See xref:02-authentication-and-access.adoc[Authentication and access].
. *Connect identity.* Configure SSO with your IdP and map IdP groups to AgentSpot roles.
. *Connect data sources and model providers.* See xref:03-connector-admin.adoc[Connector administration].
. *Set governance.* Guardrails, egress controls, audit logging, default quotas. See xref:04-usage-and-limits.adoc[Usage and limits].
. *Add pilot users.* A small group (5–15) before the wider rollout.
. *Verify end-to-end.* Sign in as a non-admin pilot user in an incognito window, run a smoke-test agent, confirm audit events appear.

== Tenant overview

The *Admin* > *Overview* page (⚠️ confirm path) shows:

* *Tenant URL and region* — match what's on your subscription.
* *AgentSpot version* — current release.
* *Activation status* — whether the feature is enabled.
* *Headline usage* — agents created, workflows running, model spend this period.
* *Headline health* — recent failures, recent guardrail blocks, recent connector errors.

Use this page as your weekly check-in. Anomalies (sudden spend spike, repeated failures) are usually visible here before they show up in tickets.

== Roles inside admin

⚠️ Confirm exact role names with [feature owner]. Typical:

* *AgentSpot Admin* — full tenant administration; everything in the admin page.
* *AgentSpot Auditor* — read-only access to audit and usage; no configuration rights.
* (Optional) *Model Provider Admin* — manage model providers only; no other admin rights.

Use the auditor role for security or finance reviewers who need visibility without the ability to change anything.

== Pilot → production: a 30-day plan

A typical rollout shape:

* *Days 1–2:* Provision. Configure SSO. Connect one data source and one model provider. Add 2 admins.
* *Days 3–10:* Add 5–15 pilot users (one or two teams). Encourage them to build small, narrow agents. Daily check on the *Overview* page; weekly check on the audit log.
* *Days 11–20:* Expand to the next 2–3 teams. Promote successful pilot agents from private to group audience. Add additional connectors as use cases emerge.
* *Days 21–30:* Tenant-wide rollout. Set production quotas. Establish a 30-day review cadence with the admin team.

== When to escalate to ThoughtSpot

Contact ThoughtSpot Support when:

* Provisioning fails or the tenant doesn't appear in *Features*.
* A built-in connector is unreachable from your tenant's region.
* Audit data is missing or incomplete.
* You suspect a security incident (treat as urgent).
* You hit a hard tenant-level limit and need it raised.

For everything else (configuration, governance, agent quality), the admin page plus the rest of these docs is enough.
